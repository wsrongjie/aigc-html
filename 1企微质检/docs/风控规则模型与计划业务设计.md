# 风控规则、模型与计划业务设计

> 状态：逐轮讨论中  
> 当前完成：风控规则、风控模型核心业务与交互原型  
> 后续待设计：风控计划、运行与复核闭环

## 0. 已确认设计决策

1. 风控规则采用“风险领域 → 风险主题 → 原子规则 → 场景策略”四层结构。
2. 同一原子规则可以绑定企微聊天、营销素材、直播等不同场景策略，不为每个渠道复制一套业务定义。
3. 首期规则中心只开放语义内容规则，不保留用户可配置的关键词、正则或词典规则。
4. 关键词可以作为模型内部召回特征，但不作为独立规则、风险结论或用户维护对象。
5. 行为阈值、业务状态和复合规则保留数据扩展能力，首期不开放完整配置器。
6. 刚性红线和策略规则作为规则属性；系统不设计甲方内部审批流程，有权限的用户仍可停用，但需醒目提示并记录操作日志。
7. 规则不绑定模型、组织、员工、运行时间、通知人和任务时限；这些分别属于风控模型和风控计划。
8. 规则命中只产生候选风险判断，不直接产生员工违规、罚单、退款或客户拦截结论。
9. 一个风控模型可以绑定多条原子规则，识别结果仍需精确回溯到具体规则及其版本。
10. 风控模型发布前必须支持测试验证；测试用于验证识别效果，不替代甲方内部审批决策。
11. 识别敏感度采用“模型统一默认值 + 个别规则单独覆盖”的配置方式。
12. 模型发布采用混合门槛：技术验证失败时阻止发布；业务效果指标不达标时强提醒，有权限的用户填写原因后仍可发布并留痕。
13. 风控模型不关联企微、营销素材、直播等具体业务场景；模型负责关联并执行预先配置的风控规则，业务数据来源和执行方式由风控计划配置。
14. 不单独建立“常规行情、波动行情、极端行情”等策略档位对象；需要启用哪些风险判断，以及其识别敏感度和展示优先级，通过模型与规则的关联配置表达。

## 1. 风控规则的目标

风控规则负责回答：**什么业务行为可能构成什么风险，以及需要什么证据才能判断。**

规则中心不负责：

- 选择底层模型；
- 配置模型阈值和识别敏感度；
- 指定检查组织、员工和企微账号；
- 配置 T-1 运行时间；
- 决定通知对象和任务负责人；
- 自动处罚员工或执行退款、拉黑、拦截。

## 2. 四层对象结构

```text
风险领域
  ↓
风险主题
  ↓
原子规则
  ↓
场景策略
```

### 2.1 风险领域

最高层业务归类，首期建议包括：

- 营销合规；
- 投顾服务合规；
- 客诉风险；
- 客户风险；
- 交易与适当性；
- 员工资质与行为；
- 数据安全与权限。

### 2.2 风险主题

表示具体风险问题，例如：

- 承诺收益；
- 误导性宣传；
- 夸大宣传；
- 越界指导操作；
- 风险提示不足；
- 投诉倾向；
- 退款倾向；
- 极端情绪；
- 客户身份异常；
- 适当性不匹配。

风险主题只负责分类，不直接执行判断。

### 2.3 原子规则

原子规则表示一个可以独立判断的业务命题，例如：

> 员工是否以肯定性表述，向客户承诺本金安全、固定收益或必然盈利。

原子规则必须满足：

- 每条规则只判断一个业务问题；
- 能给出疑似成立、不成立或证据不足；
- 具备正例、反例和模糊案例；
- 命中后能够定位具体证据；
- 不直接包含检查范围和运行时间；
- 不直接绑定具体模型；
- 不直接形成处罚或最终违规结论。

### 2.4 场景策略

同一原子规则在不同接入语境下具有不同输入、上下文和证据要求。下表用于帮助规则配置者定义适用边界，不代表模型绑定具体业务来源；执行时点、数据来源和实际处理流程仍由风控计划配置。

| 配置项 | 企微聊天 | 营销素材 | 直播 |
| --- | --- | --- | --- |
| 执行时点 | T-1 检查前一天聊天 | 发布前预审 | 直播结束后审查 |
| 判断对象 | 员工与客户沟通 | 素材整体内容 | 直播人员发言和画面 |
| 上下文 | 前后消息或时间窗口 | 标题、正文、图片、音视频 | 前后时间片、画面、评论 |
| 证据 | 消息、会话、发送人 | 素材版本和风险位置 | 转写、时间点、录像 |
| AI 输出 | 疑似风险及依据 | AI 预审建议 | 事后风险点 |
| 人工输出 | 误判、风险成立、确认违规、证据不足 | 通过、修改后通过、不通过、退回修改 | 误判、风险成立、确认违规、证据不足 |

## 3. 首期规则类型

### 3.1 首期开放

只开放**语义内容规则**，用于：

- 企微聊天 T-1；
- 营销素材发布前预审；
- 直播内容事后审查；
- 后续外呼或电话录音审查。

### 3.2 首期不开放

- 关键词、正则和词典规则；
- 行为次数或时间阈值规则；
- 订单、合同等业务状态组合规则；
- 跨事件复合规则。

这些能力可以由技术实现或后续版本提供，但不作为首期规则中心的用户配置对象。

## 4. 原子规则字段

### 4.1 基础信息

- 规则 ID；
- 规则名称；
- 风险领域；
- 风险主题；
- 规则说明；
- 规则属性：刚性红线或策略规则；
- 制度或业务依据；
- 规则负责人；
- 当前版本；
- 启用状态。

### 4.2 适用条件

- 适用主体：销售、投顾、策划、客户、直播人员等；
- 业务阶段：获客、成交前、成交后、服务期、客诉期；
- 适用渠道：企微、素材、直播、外呼；
- 产品范围；
- 客户范围；
- 内容模态：文字、语音、图片、视频；
- 排除主体、场景或产品。

以上只定义规则的业务适用边界，不选择具体组织、员工和客户。具体运行范围由风控计划配置。

### 4.3 判断标准

- 正向判定条件；
- 排除条件；
- 必须同时满足的条件；
- 任意满足的条件；
- 所需上下文；
- 需要关联的业务事实；
- 证据不足条件；
- 容易误判的表达；
- 正例、反例和模糊案例。

### 4.4 结果定义

- 规则严重度基准；
- 建议风险主题；
- 最低证据要求；
- 是否必须人工复核；
- 建议处理方向；
- AI 输出格式要求。

## 5. 规则版本与启停

规则生命周期：

```text
草稿 → 已发布 → 已停用 → 已废弃
```

规则一旦被模型或计划引用：

- 已发布版本不可直接覆盖修改；
- 修改时生成新版本；
- 历史运行保留旧版本和规则快照；
- 停用只影响后续绑定和后续运行批次；
- 已运行结果继续显示当时版本；
- 支持版本对比和回滚；
- 记录修改人、修改时间和修改内容；
- 停用刚性红线时醒目提示风险，但不在系统内设计审批流程。

## 6. 规则示例：明确承诺保本或收益

### 基本信息

- 规则名称：明确承诺保本或收益；
- 风险领域：营销合规；
- 风险主题：承诺收益；
- 规则属性：刚性红线；
- 严重度基准：高；
- 适用主体：销售人员、非授权投顾人员；
- 适用阶段：获客、成交前。

### 正向判定

- 明确表示客户一定可以盈利；
- 明确承诺本金不会亏损；
- 明确承诺固定收益率；
- 表示发生亏损由员工或公司兜底；
- 使用变体、谐音、图片符号表达相同含义。

### 排除条件

- 客户转述其他机构的承诺；
- 员工明确表示不能保证收益；
- 引用监管制度说明禁止承诺收益；
- 仅陈述已经发生且可以核实的历史事实；
- 无法确认说话主体或指向对象。

### 最低证据

- 原始内容；
- 发送主体和接收对象；
- 前后文；
- 内容时间；
- 消息、素材版本或直播时间点；
- 使用的规则版本。

### 允许的 AI 输出

- 疑似承诺收益；
- 未发现承诺收益；
- 证据不足；
- 需要人工复核。

### 不允许的 AI 输出

- 员工已违规；
- 直接生成罚单或扣款；
- 强制退款；
- 客户拉黑或业务拦截。

## 7. 风控模型：已确认边界

### 7.1 模型与规则的关系

- 一个风控模型可以绑定多条原子规则；
- 每条绑定关系必须固定规则版本；
- 模型运行结果必须精确到命中的具体规则；
- 同一次内容检查可以同时命中多条规则；
- 规则的严重度基准不因模型敏感度变化而改变；
- 风控模型不配置企微、营销素材、直播等具体业务场景；
- 风控模型不配置具体组织、员工、客户、执行日期和通知对象；
- 业务数据来源、执行时点、执行范围和通知对象统一由风控计划负责；
- 同一个已发布模型可以被不同业务场景的多个风控计划复用。

### 7.2 测试验证要求

风控模型发布前必须执行测试验证。测试验证至少需要覆盖：

- 单条样本调试；
- 批量测试集验证；
- 按规则查看测试结果；
- 定位原始内容、上下文和模型判断依据；
- 识别疑似命中、未命中、证据不足和运行失败；
- 保存模型版本、规则版本、测试集版本和运行参数快照；
- 保留测试人、测试时间和测试结果记录。
- 模型规则、敏感度、阈值或复核配置变化后，已有测试立即失效，必须重新验证；
- 测试运行绑定独立运行标识和配置指纹，离开当前模型后，旧异步结果不能写入其他模型。

测试验证负责提供效果证据，不在系统内替甲方完成模型发布审批。

### 7.3 识别敏感度

模型设置统一的默认识别敏感度，支持低、中、高三个等级；绑定规则时，可以为少量特殊规则覆盖模型默认值。

- 未配置规则级敏感度时，继承模型默认值；
- 配置规则级敏感度后，只影响该规则的召回和复核策略；
- 敏感度变化不修改规则严重度基准；
- 敏感度配置必须进入模型版本和运行快照；
- 历史运行结果继续显示当时实际生效的敏感度。

### 7.4 测试方式

模型测试支持：

1. 单条样本调试：查看各规则的命中结果、证据位置、上下文和判断依据；
2. 测试集验证：使用已标注样本批量验证，按模型和规则查看效果；
3. 版本对比：同一测试集对比新旧模型，定位新增命中、消失命中和判断变化。

测试指标至少包括：

- 准确率；
- 召回率；
- 误报率；
- 漏报率；
- 证据完整率；
- 运行失败率；
- 平均处理时长。

测试集支持系统预置、客户上传和从历史人工复核结果沉淀。涉及真实客户数据时，需要遵循数据权限和脱敏规则。

每次测试必须冻结以下快照：

```text
模型版本 + 规则版本 + 测试集版本
+ 敏感度配置 + 上下文配置 + 底层能力版本
```

### 7.5 发布门槛

模型发布采用混合门槛：

**技术硬门槛：**

- 测试未完成；
- 模型无法正常运行；
- 输出结构无法解析；
- 无法关联规则版本；
- 无法生成或回溯证据；
- 关键输入处理链路失败。

出现以上问题时，系统阻止发布。

**业务效果门槛：**

- 准确率、召回率低于目标；
- 误报率或漏报率超过目标；
- 个别规则表现明显退化；
- 新版本相对旧版本效果回退。

出现业务效果问题时，系统醒目提示风险。有发布权限的用户可以填写发布原因后继续发布，系统记录操作者、时间、指标差异和发布原因，不增加内部审批流程。

### 7.6 模型的业务无关输入

企微消息、营销素材、直播录像、外呼录音等原始数据，需要先在计划执行链路中转换为统一的标准化内容对象，再提交给风控模型。

标准化内容对象至少包括：

- 原始文字或语音转写；
- 图片 OCR 和图片内容描述；
- 视频语音转写、画面描述和时间轴；
- 内容主体、接收对象和发生时间；
- 前后文或关联内容；
- 原始数据来源标识和回跳地址；
- 产品、订单、客户等可用的关联业务事实；
- 数据完整性和转写质量信息。

模型只依据标准化内容和已关联规则输出风险判断，不直接处理“企微检查”“素材送审”或“直播审查”等业务流程。

### 7.7 模型与规则的关联配置

创建模型时，从规则中心选择已经配置并发布的规则。每条模型与规则的关联关系支持设置：

- 是否启用；
- 绑定的规则版本；
- 是否继承模型默认敏感度；
- 规则级敏感度覆盖；
- 展示优先级；
- 置信度门槛；
- 是否必须进入人工复核；
- 测试结果和最近一次验证状态。

市场行情或业务策略变化时，用户调整的是模型中的规则关联配置，并生成新的模型版本；不另外创建独立的行情策略档位。

### 7.8 模型管理页面结构

风控模型管理采用“目录列表 + 独立二级页”的页面结构，不在列表右侧使用狭窄抽屉承载复杂配置。

模型目录展示：

- 模型名称和编号；
- 当前状态；
- 默认识别敏感度；
- 关联规则数量；
- 最近测试结果；
- 当前版本；
- 负责人和更新时间；
- 被风控计划引用的数量。

模型创建与修改采用五步流程：

```text
基础信息 → 关联规则 → 识别配置 → 测试验证 → 确认发布
```

模型状态包括：

```text
草稿 → 测试中 → 可发布 → 已发布 → 已停用
```

其中：

- 已发布版本不可直接覆盖修改；
- 继续修改时创建新的草稿版本；
- 新版本保留稳定模型身份，并将上一版本的规则配置、测试指标、测试集和发布原因保存为独立历史快照；
- 技术验证未通过时不可进入发布；
- 业务效果指标未达标时显示风险提示，有权限用户填写原因后可以发布；
- 发布时冻结模型配置、规则版本、识别参数和测试快照；
- 模型页面不提供业务数据来源、执行范围和运行时间配置。

## 8. 后续待设计

1. 风控模型深化：标准化输入协议、多模态能力组合和异常降级策略。
2. 测试验证深化：测试集标注流程、版本维护和异常样本闭环。
3. 风控计划：运行范围、T-1 时间、素材送审、直播事后审查、计划版本和批次快照。
4. 运行闭环：风险信号、风险事件、人工复核、任务处置和效果评测。
