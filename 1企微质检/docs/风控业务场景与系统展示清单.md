# 风控业务场景与系统展示清单

> 分析日期：2026-10-23  
> 资料范围：4 份客户访谈转写、客户当前合规系统与订单系统功能梳理  
> 目标：识别客户业务中的完整风控场景，并明确这些场景应如何在后续业务系统中展示。  
> 边界：测试环境页面只能证明字段或入口存在；真实流程、接口、数据覆盖、权限和模型效果仍需验证。

## 1. 结论

依据访谈、页面线索和产品分析，可以归纳出 **8 个风控领域、55 个候选业务场景**。这些场景既包含客户明确需求，也包含页面字段所表达的控制点和待确认的产品建议：

1. 营销内容与素材风控；
2. 股票报告与直播风控；
3. 企微营销沟通与员工行为风控；
4. 成交、适当性与履约风控；
5. 客诉、退款与外诉处置；
6. 客户风险与业务拦截；
7. 员工资质、组织与责任管理；
8. 数据调阅、权限与审计。

这些场景不能全部做成并列菜单，也不能按 55 项直接统计风险规模。同一问题可以合法关联预警、咨诉、正式投诉、退款单、员工违规案件、客户标签和多个处置任务；系统需要避免的是 AI 重复创建同一信号、事件或处置任务，而不是删除这些各自具有独立状态的业务记录。

推荐采用：

- **一个风险事件主记录**：聚合同一客户、风险主题、责任对象、业务对象和时间窗口内的相关信号；
- **多个业务对象关联视图**：客户、员工、素材、直播、订单等页面展示同一事件的摘要；
- **保留独立业务对象**：投诉、退款、违规案件和处置任务分别保留自身编号、状态和责任人；
- **原始业务状态回跳**：订单、合同、退款、会话、素材原文仍以来源系统为准；
- **AI 结果与人工结论分开**：AI 命中只能显示为风险信号，不能直接显示为“员工已违规”。

## 2. 三种已经确认的执行方式

| 风控场景 | 执行方式 | 系统结果性质 |
| --- | --- | --- |
| 企微聊天 | T-1，检查前一天聊天记录 | 生成风险信号或待复核事件，不实时阻断聊天 |
| 营销素材 | 发布前送审 | AI 输出预审建议；通过、修改后通过或不通过只能作为授权人工审核决定，是否强制阻断由原业务系统决定 |
| 直播内容 | 直播结束后审查 | 生成直播风险点、关联证据和待复核事件，不中断直播 |

订单、合同、实名、适当性、支付和退款等场景主要是**业务状态校验与流程控制**，不宜机械套用 T-1 模型计划；它们的具体触发时机需结合原业务流程确认。

## 3. 统一展示原则

### 3.1 风险严重度、模型置信度和展示优先级分开

| 字段 | 含义 | 是否可按行情调整 |
| --- | --- | --- |
| 规则严重度基准 | 规则对该类行为后果的预设，例如承诺收益为高风险 | 原则上不随行情改变 |
| 模型置信度 | 模型对本次判断的把握程度 | 随模型输出变化 |
| AI 建议事件等级 | 模型结合规则基准、上下文和证据给出的建议等级，不是人工结论 | 可受识别方案影响，但必须保留计算依据 |
| 人工确认等级 | 授权人员复核后的事件等级 | 由人工裁决，保留调整理由 |
| 识别敏感度 | 模型召回范围，低/标准/高敏感度 | 用户可根据行情配置 |
| 展示优先级 | 当前最应该先处理哪些事件 | 用户可按行情策略调整 |
| 人工结论 | 误判、风险成立、确认违规、证据不足 | 只能由授权人员产生 |

模型置信度在完成校准前只能显示为模型分数，不能暗示为真实发生概率。展示优先级可以影响队列排序，但不能覆盖制度规定的处置期限。

### 3.2 同一事件在不同页面展示，但不复制

| 页面 | 展示方式 |
| --- | --- |
| 风控待办 | 风险事件主记录，支持处理、复核、延期、结案 |
| 客户档案 | 展示客户相关风险摘要、历史事件、当前风险状态和拦截结果 |
| 销售档案 | 展示员工相关事件、企微账号、人工违规结论及整改记录 |
| 素材档案 | 展示素材版本、送审记录、风险位置、修改建议和最终审核结果 |
| 直播档案 | 展示直播场次、时间轴风险点、涉及人员和事后审查结果 |
| 订单档案 | 展示实名、风测、合同、回访、退款等独立状态及关联风险 |
| 管理报表 | 聚合同一事件口径，区分本期发生和当前积压 |

### 3.3 所有风险事件的公共展示字段

- 风险事件 ID、风险领域、场景和风险分类；
- 规则严重度基准、AI 建议事件等级、人工确认等级、模型置信度和展示优先级；
- AI 分析结果、人工判定、事件生命周期、任务状态和复发关系分别展示，不合并成一个“当前状态”；
- 关联客户、员工、企微账号、部门、主管和其他协同人员；
- 关联消息、会话、素材、直播、股票报告、订单、合同或退款单；
- 触发时间、首次发现、最近触发、重复次数和处理截止时间；
- 命中规则、规则版本、模型版本、行情策略版本和计划运行批次；
- 证据摘要、证据采集时间、来源更新时间、原始记录回跳和无权/过期/缺失状态；
- AI 原因与建议、人工结论、处理动作、复核人、结案原因及完整操作日志。

### 3.4 风险事件拆分与合并规则

事件自动聚合至少需要同时考虑：

- 稳定客户 ID；
- 风险主题或根因；
- 涉及员工、素材、直播或订单等责任对象；
- 关联产品、订单、退款单或活动等业务对象；
- 配置的时间窗口。

同一客户在同一天提出“退款”和举报另一名销售违规，不应仅因客户相同而合并；同一客户围绕同一亏损问题连续多次抱怨，可以聚合为同一事件并保留全部原始触发次数。系统必须支持授权人员拆分、合并和撤销合并，并记录操作原因。

### 3.5 场景索引不是风险分类

55 个场景混合了渠道、业务阶段、流程节点和横向控制能力，设计时每条场景需要额外标记：

- 风险主题：承诺收益、误导宣传、投诉、退费、适当性等；
- 渠道或对象：企微、外呼、素材、直播、客户、员工、订单等；
- 流程阶段：发布前、成交前、成交后、服务中、投诉处置等；
- 控制类型：模型识别、人工审核、状态校验、业务限制、权限审计等；
- 证据属性：客户明示、页面入口/字段、分析推导、产品建议、本轮新增确认。

例如，C01/C02 是发布前内容视角，M02/M04 是素材实际发送后的员工沟通视角；L05、M07、E01 可能分别是直播渠道信号、企微信号和同一客诉事件。页面可以按这些视角展示，但统计风险规模必须按风险事件 ID 去重。

### 场景清单

| ID | 业务场景 | 主要风险 | 执行方式 | 证据属性 |
| --- | --- | --- | --- | --- |
| M01 | 成交前销售沟通 | 承诺收益、保证效果、保本保收益 | T-1 | 客户明示 + 本轮用户确认时点 |
| M02 | 营销话术和产品介绍 | 误导性宣传、夸大效果、高预期、极限用词 | T-1 | 客户明示 + 本轮用户确认时点 |
| M03 | 个股和仓位沟通 | 无资质或营销场景下明确要求买入、卖出、加仓、减仓，或不当仓位指导 | T-1 | 客户明示；角色与服务边界待制度确认 |
| M04 | 退费及服务承诺 | 宣传无理由退费、擅自兜底、承诺未写入产品服务 | T-1 | 客户明示 |
| M05 | 风险提示与产品匹配沟通 | 风险揭示不足、产品内容表述错误、越权承诺 | T-1 | 访谈方向 + 待制度确认 |
| M06 | 成交后服务沟通 | 服务态度、辱骂、推诿、错误安抚、未按要求处理客户 | T-1 | 客户明示 + 页面分类 |
| M07 | 客户投诉、退款和外诉意图 | 抱怨、亏损、退费、投诉监管、拨打投诉电话等 | T-1，高危优先展示 | 客户明示 |
| M08 | 客户情绪变化 | 愤怒、极端表达、反复发酵；纯文字与语音/表情结果不一致 | T-1，多模态 | 客户明示 + 讨论认可 |
| M09 | 企微敏感行为 | 发红包、发名片等已配置行为；实际监控主体仍需核实 | T-1 或规则触发 | 页面字段，主体说明存在歧义 |
| M10 | 外呼和电话沟通 | 不当承诺、风险提示不足、客诉或退费表达未识别、录音未留痕 | 通话后审查方式待确认 | 通话记录页面 + 留痕访谈 + 产品建议 |

### 需要特别处理的判断边界

- 客户提到“稳赚不赔”不等于销售承诺收益，必须识别说话主体和上下文；
- 评论监管政策或客户抱怨监管，不等于客户正在投诉公司；
- “亏损”可能是市场观点，也可能是客户真实抱怨；
- 销售说“可以关注”与明确要求“买入、卖出、加仓、减仓”应分开；
- 客户历史表示可以承受风险，不自动免除员工的合规责任，只能作为责任判断证据；
- 图片符号、火箭、金元宝、表情、字号和色彩也可能构成诱导，需要保留多模态证据。
- “买入、卖出、仓位”等词本身只能作为候选信号；必须先识别发言主体、执业资质、服务阶段和适用制度，销售营销越界与正式投顾服务不能共用同一结论规则。

### 业务系统需要展示

- T-1 检查日期、覆盖员工/账号/客户数量、消息量和数据完整性；
- 员工、真实员工 ID、企微账号、组织、主管和客户；
- 风险消息、前后文、语音转写、语音情绪、图片/表情描述及原消息回跳；
- 风险分类、严重度、置信度、显示优先级、命中规则和排除条件；
- 同一客户当天及历史相关信号，是否合并为同一风险事件；
- AI 建议、人工判定、责任归属、整改或客户安抚任务；
- 误判原因和人工标记，回流效果评测。
- 外呼场景还需展示通话方向、坐席、客户、开始/结束时间、时长、接通状态、录音、转写、风险时间点和留痕完整性。

### 展示入口

## 13. 风险结果与流程状态展示规范

以下内容必须分别保存和展示，不能压缩成一个状态字段：

| 维度 | 建议取值 | 说明 |
| --- | --- | --- |
| AI 分析结果 | 未分析、疑似风险、未发现风险、分析失败、证据不足 | 只是模型输出，不对员工定责 |
| 人工判定 | 未判定、误判、风险成立、确认违规、证据不足、无法判断 | 只有“确认违规”可以作为员工定责结论 |
| 事件生命周期 | 新发现、待复核、已确认、处置中、观察中、已关闭 | 描述风险事件整体所处阶段，不覆盖人工判定 |
| 任务状态 | 待领取、待处理、处理中、待复核结案、已完成、延期、逾期、取消 | 一个事件可以存在多个不同负责人的处置任务 |
| 复发关系 | 首次事件、关联历史、复发、合并、拆分 | 这是事件之间的关系，不是流程状态 |
| 素材审核决定 | 待审核、通过、修改后通过、不通过、退回修改 | 必须区分 AI 预审建议和授权人工最终决定 |

例如，一个事件可以同时是“人工确认违规＋事件处置中＋员工整改任务逾期”；误判事件也需要进入“已关闭”，不能因为人工判定为误判就丢失流程和审计记录。

## 14. 建议的建设顺序

### 第一批：直接影响近期投诉的优先建设候选

- M01—M08：企微聊天 T-1 风控；
- E01—E08：客诉、退费和外诉处置；
- U03—U04：先展示现有客户风险等级和业务限制摘要；动态分级规则属于后续建设；
- S02—S04：员工账号关联、组织归属和人工违规复核；
- D01—D05：证据权限、审计和数据完整性。

E06—E07 的退款闭环依赖 T04 合同状态、T07 财务状态以及退款实际结果可读，虽然交易与履约整体列在第三批，这些依赖项必须随首期客诉闭环优先验证。

### 第二批：内容风控建设候选

- C01—C06、C08：素材发布前预审和质量检查；
- C07：审核版本与实际分发一致性，属于产品建议；
- L03—L06：直播登记、留痕和事后审查；
- L01—L02：股票报告与诊股审核。

### 第三批：依赖原业务系统状态机验证

- T01—T08：实名、适当性、合同、支付、回访和服务；
- U01、U02、U05：外部名单、异常潜客及风险解除；
- S01、S05：资质核验、罚单、人事与培训联动。
- M09—M10：敏感行为监控主体及外呼审查方式确认后建设。

该顺序是产品建议。甲方目前明确的优先目标只有“先降低客户投诉”，其他模块之间的正式排序仍需业务负责人确认。

## 15. 上原型前仍需确认的问题

1. T-1 的“前一天”按自然日还是业务日计算，计划几点开始、几点前必须出结果；
2. 素材最终人工审核决定是否由原业务系统强制阻断发布，以及 AI 预审建议是否仅供审核人参考；
3. 直播高风险经人工确认后，是否自动生成员工整改任务并计入质检统计；
4. 投诉处理、咨诉列表和客诉预警三者在甲方内部的正式业务边界；
5. 实名、风测、合同、回访和服务开通之间有哪些后端强制依赖；
6. 退款页面“成功”是否代表出款指令成功、渠道处理成功还是客户实际到账；
7. 客户风险等级由谁维护、有效期多久，以及解除和申诉机制；
8. 企微语音、外呼录音、直播录像和评论的真实采集覆盖率及保存期限；
9. AI 判断所用的行情阶段由用户手动选择，还是接入行情数据自动建议；
10. 哪些风险规则属于不可关闭的刚性红线，哪些只影响显示优先级和人工复核顺序。
