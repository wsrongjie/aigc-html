# 风控模型管理原型 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task.

**Goal:** 建立一个与业务场景解耦、支持多规则关联、测试验证和版本发布的风控模型管理交互原型。

**Architecture:** 新建独立单文件 HTML 原型，以内存演示数据驱动模型列表、模型详情、创建编辑、测试验证和发布流程。风控模型只组合规则及识别参数，企微、素材、直播、组织、员工和执行时间均不进入模型字段；这些能力留给后续风控计划。入口页只负责跳转，不与资产中心共享运行状态。

**Tech Stack:** 原生 HTML、CSS、JavaScript；Python Playwright 浏览器自动化；本地 HTTP Server。

---

### Task 1: 建立风控模型原型验收标准

**Files:**
- Create: `tests/risk-model.spec.py`

**Steps:**
1. 编写入口、模型列表、二级页、创建流程、规则多选、敏感度覆盖、测试验证和发布门槛断言。
2. 增加“模型页不存在具体业务来源字段”的边界断言。
3. 增加 1440、1024、390 三种宽度的横向溢出和关键内容可见性检查。
4. 运行 `python tests/risk-model.spec.py`，确认在实现前失败。

### Task 2: 创建独立风控质检原型

**Files:**
- Create: `风控质检-交互原型.html`

**Steps:**
1. 建立深色侧栏、顶栏、响应式主内容和演示环境提示。
2. 建立风控规则、风控模型、风控计划、风险结果导航，其中仅风控模型开放完整功能。
3. 建立模型列表及状态、负责人、规则数、版本和测试状态筛选。
4. 建立模型详情二级页，展示规则配置、测试概况、版本和操作记录。
5. 验证页面无脚本错误、无失败资源且窄屏无整页横向滚动。

### Task 3: 实现模型创建和规则关联

**Files:**
- Modify: `风控质检-交互原型.html`

**Steps:**
1. 建立基础信息、规则关联、参数配置、测试验证、确认发布五步流程。
2. 支持从已发布规则库筛选并关联多条规则。
3. 支持模型默认敏感度以及规则级继承/覆盖、优先级、置信度和人工复核配置。
4. 阻止未关联规则、缺少必填信息或未完成技术验证的模型发布。
5. 确认表单中不存在企微、素材、直播、组织、员工和运行时间字段。

### Task 4: 实现测试验证和混合发布门槛

**Files:**
- Modify: `风控质检-交互原型.html`

**Steps:**
1. 支持单条调试、测试集验证和版本对比三种方式。
2. 展示模型总体指标和规则级准确率、召回率、误报率、漏报率、证据完整率、失败率与耗时。
3. 支持下钻查看误报、漏报及证据定位。
4. 技术验证失败时禁止发布。
5. 业务指标不达标时要求填写原因后允许发布，并记录操作日志。
6. 发布后冻结版本；继续修改时生成新的草稿版本。

## 实施约束

- 所有数据均为虚构演示数据，不接入真实模型、客户系统或接口。
- 不在模型配置中加入具体业务来源和执行范围。
- 不设计甲方内部发布审批流程。
- 不执行 `git add`、`git commit` 或 `git push`。
