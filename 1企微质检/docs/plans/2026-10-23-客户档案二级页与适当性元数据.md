# 客户档案二级页与适当性元数据实施计划

> **For Codex:** 用户确认后按本计划实施；不执行 Git 操作。

**目标：** 将客户档案从右侧抽屉改为主内容区二级页面，并补充金融投顾业务所需、来源可追溯且默认脱敏的客户元数据。

**架构：** 客户目录仍是一级列表页，点击客户后进入同一主内容区的二级档案页；侧栏“客户档案”保持选中，面包屑显示“客户档案 / 客户姓名”。客户页状态与通用资产抽屉分离，关联资产仍可用现有抽屉查看。所有新增客户字段按来源快照留存，不通过姓名、聊天、证件号或模型推断。

**技术栈：** 单文件 HTML、CSS、原生 JavaScript、Python Playwright 浏览器验证。

---

## 一、已确定的交互方案

采用“目录 → 全宽二级档案页”的结构，不新开浏览器页面，也不使用客户抽屉。

- 客户目录点击姓名或“查看档案”，主内容区切换为客户二级页；顶部提供返回客户目录按钮。
- 侧栏继续高亮“客户档案”；桌面和移动端面包屑显示客户层级。
- 返回目录时恢复已提交查询、草稿、分页、表格横纵滚动位置和原触发按钮焦点。
- 从资产、订单、商品、员工等抽屉点击客户时，先保存入口上下文，再进入客户二级页；返回时恢复原页面及原抽屉对象、标签和返回栈。
- 客户页内点击订单、合同、消息、素材等继续复用资产抽屉；关闭抽屉后仍停留在客户二级页及原标签位置。
- 浏览器刷新后回到客户目录，不伪装成真实路由或永久链接；生产实现建议使用 `/customers/:customerId`。

## 二、二级页面信息架构

页面顶部是紧凑客户摘要，不使用大卡片堆砌：客户姓名、统一客户编号、来源服务状态、投资者类型、风险等级、最近归档更新时间，以及脱敏手机号/微信号。缺失字段明确显示“未提供”。

二级页使用七个标签：

1. **档案总览**：跨系统身份、基础联系信息、适当性摘要、实际对接人员、关联资产分类、完整记录时间线。
2. **沟通记录**：原有多销售、多企微账号聊天归档，保留会话与账号来源。
3. **投资者适当性**：投资者类型、实名状态、风险承受等级、测评时间与有效状态、财务区间、经验、目标、风险偏好、诚信与受益人声明。
4. **交易与服务**：订单、已购商品、服务期间、支付和服务状态；商品当前配置与订单成交快照继续分开。
5. **内容与直播**：实际收到的素材/研报版本，以及来源直播动作，不把收到内容解释为阅读或意向。
6. **合同与回访**：购买合同、回访确认、退款协议及来源审核状态。
7. **咨诉与退款**：咨询、投诉、退款申请及处理历史，继续区分申请、审批、合同与执行。

## 三、客户元数据字段

只给原6名完整业务客户补充虚构演示快照；114条纯目录样本保持来源仅提供的字段，不批量编造画像。

### 1. 基础身份与联系方式

- 统一客户编号、姓名、性别、年龄段。
- 手机号、个人微信号、企微外部联系人 ID、小程序 OpenID/UnionID。
- 所在地区到省/市级、职业类别、学历区间。
- 实名状态、证件类型、证件号码脱敏摘要、实名时间、认证方式。

年龄段、性别、地区、职业和学历只读取明确来源字段；不从身份证号、姓名、定位或聊天内容推导。手机号、微信号和证件号默认脱敏；本原型不模拟“查看明文”权限。

### 2. 投资者适当性

- 投资者类型：普通投资者 / 专业投资者 / 未提供。
- 风险承受等级、测评日期、有效期或有效状态、问卷版本、测评来源。
- 收入来源、年收入区间、金融资产区间、负债情况。
- 投资知识、投资年限、参与过的投资品种。
- 投资期限、关注品种、期望收益区间等投资目标。
- 风险偏好、最大可承受损失区间。
- 诚信记录状态、实际控制人与实际受益人声明。

这些字段只展示来源系统的记录和时点，不在资产模块重新评分、不生成适当性匹配意见，也不从订单金额或聊天语义反推资产、收入和风险偏好。

### 3. 获客、服务与数据治理

- 注册时间、首次添加企微时间、来源渠道、引流媒介/活动、首次对接员工。
- 当前服务商品、服务状态、服务期间、最近订单时间、实际对接人员。
- 字段来源系统、来源记录 ID、来源更新时间、数据状态（已提供 / 未提供 / 待核验）。

营销来源与当前客户归属分开；历史对接人员不会被标记成当前归属。服务状态取订单来源快照，退款申请不直接覆盖服务状态。

## 四、法规和产品边界

- 《证券期货投资者适当性管理办法》第六条列出基本信息、财务状况、投资经验、投资目标、风险偏好、诚信、控制人与受益人等信息；第十三条要求建立评估数据库并及时更新。
- 《证券投资顾问业务暂行规定》第十一条要求了解身份、财产与收入、证券投资经验、投资需求和风险偏好，并记录保存风险承受能力评估。
- 《个人信息保护法》第六条要求目的明确、直接相关和最小范围；敏感个人信息需要更严格保护。原型只展示虚构、脱敏快照，生产需结合字段级权限、访问审计、加密和保存期限。

## 七、主要风险

- 客户链接分布在目录、时间线、聊天、订单、商品、员工和直播中，统一改入口容易造成返回栈或标签状态回归。
- 原客户和员工共用 `profileDetail`，拆分时要确保员工账号多选筛选完全不受影响。
- 适当性字段属于高敏感业务数据；不能为了页面丰满而给114条目录样本生成性别、年龄、收入、风险等级或投资偏好。
- 年龄段、风险等级和投资者类型都带有效时点；页面必须同时展示来源更新时间，不能把过期测评当作当前有效结论。
- 静态原型没有真实权限体系，不能提供看似可用的“查看完整手机号/身份证”按钮。
- 本轮仅做结构化留存和展示，不新增风险评分、销售建议、适当性自动判断或任何写回客户原系统的操作。

## 八、验收标准

- 所有客户入口均进入主内容区二级页，`#detail` 客户抽屉不打开。
- 返回目录或来源对象后，查询、分页、滚动、标签和焦点可恢复。
- 六名业务客户展示不同的虚构元数据；纯目录客户只显示真实已有字段及“未提供”。
- 手机、微信、证件和财务字段按设计脱敏或区间化；导出不泄露明文。
- 客户页所有关系仍按稳定客户 ID 汇集，同名客户不合并。
- 客户页面在五种宽度无整页横向溢出，标签、长表和聊天在局部滚动。
- 原209项基础回归、55项商品检查及新增专项全部通过，浏览器无脚本、控制台或资源请求错误。
