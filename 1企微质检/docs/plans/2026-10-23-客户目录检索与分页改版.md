# 客户目录检索与分页改版实施计划

目标：将客户卡片页改为适合大规模客户库使用方式的检索型目录，先定位客户，再查看完整档案。

授权：用户已确认前一轮方案并要求「改一版看看效果」，直接实施，无需重复确认。

架构：单文件 HTML/CSS/JavaScript。客户目录使用独立筛选状态和分页查询适配层；本地虚构样本用于演示，每次仅将当前页客户渲染为表格。源记录预先建立目录索引，避免在列表为每个客户反复计算完整关联资产与会话。现有客户详情按点击加载，销售档案保持原样。

## 文件与步骤

1. 修改 `企业数据资产中心-交互原型.html`：独立客户目录，移除客户页全库统计与人物卡片；紧凑表格、精确检索模式、来源/销售/团队/服务状态/最近归档更新日期筛选，明确查询后生效。
2. 增加少量虚构的客户身份目录样本，使默认 50 条分页可实际演示；保留六名完整业务样本，不制造额外消息、订单或会话。缺失状态显示「未提供」。
3. 电话默认脱敏；客户编号/手机号/来源客户标识支持精确检索，姓名模糊匹配。姓名与联系方式不用于自动合并身份，客户以稳定 ID 关联。
4. 客户行展示姓名与编号、脱敏联系方式、来源系统、实际对接销售、来源服务状态、最近归档更新时间及档案入口。来源映射中的对接关系与会话/消息数量分别保留。
5. 分页提供 25/50/100 条选择及上一页/下一页，默认 50；保留目录筛选和所在页，关闭详情返回原位置；导出仅当前筛选结果且电话脱敏，待提交条件不影响已生效的导出范围。
6. 更新既有浏览器回归的客户检索路径；新增有意义的检索、分页、缺失数据、脱敏、导出、详情回跳、跨页面状态隔离与窄屏验证，保存截图。
7. 进行两轮独立 Agent 对抗性只读复核，修复本次引入的问题；更新查看说明和分享包。

涉及文件：主原型、`tests/asset-center.spec.py`、新增 `tests/customer-directory.spec.py`、本计划、`outputs/asset-center/原型查看说明.md`、分享包及 `outputs/asset-center/customers/` 下截图/报告。

## 口径与风险

- 日期为最近归档更新时间，不代表最近一次沟通；对接销售不是当前客户归属，允许多人，不从姓名或消息推断归属。
- 来源服务状态只取已提供的来源字段，不能由退款申请或标签推断服务已终止；没有服务状态显示「未提供」。
- 多名销售与团队组合筛选要求同一名对接销售同时符合条件，避免跨关系误匹配。
- 本地样本与同步查询适配层仅用于原型，不代表接通权限接口、后台游标分页、索引服务或验证千万级容量。生产需要后台过滤、权限控制、索引、预汇总、稳定排序及按需加载。
- 不改变现有业务资产和媒体，不修改客户资料或既有备份，不执行 Git 操作；不用大模型生成客户评分、意向或结论。
- 测试使用独立临时 Chromium 上下文，不控制用户现有浏览器；未进行真实设备和生产验收。

## 结果

- 已将客户卡片改为紧凑检索表格，移除客户页全库统计；默认50条，支持25/50/100条、上一页及下一页。表头和操作列在列表滚动时保持可用。
- 查询条件与已生效结果分离；编号/手机号/来源ID精确查询，姓名模糊查询，来源、销售、团队、服务状态、最近归档日期可组合；销售与团队匹配同一名对接销售。
- 本地目录120条虚构身份：原6名完整业务客户及114条目录样本；资产40条、会话7个、消息30条保持原有规模。目录样本不生成额外业务记录。
- 点击客户加载既有详情；关闭后保留目录所在页和列表滚动位置。联系方式及客户导出（含查询元信息）统一脱敏。
- 查询适配层提供当前页结果；索引在明确提交新查询时刷新来源快照，翻页/界面重绘复用快照，不逐行计算完整客户详情。生产的权限、后台索引和游标分页尚未接入。
- 浏览器验证：原有74项、资产检索/折叠菜单35项、客户目录40项均通过，共149项。客户目录另使用临时一万条纯身份样本验证当前页仍只渲染50行，不据此推断生产容量。
- 已查看1440桌面、组合筛选、1280笔记本及390窄屏截图；程序布局检查覆盖1440、1280、900、390、320像素，无整页横向溢出。无脚本、控制台或资源请求错误，既有备份哈希未变。
- 两轮独立审查发现并修复：来源ID与来源条件依赖、移除条件保留其他未提交草稿、同条数源字段更新后重新查询刷新、各种检索模式和格式化手机号的导出脱敏。最终定向复验均通过。
- 验证报告与截图位于 `outputs/asset-center/customers/`，审查初始证据与修复复验分别留存，不将初始失败报告当作最终结论。
- 查看说明与分享包已更新，无Git操作。Windows原生输入法、客户生产系统、真实设备与千万级后端容量未验收。
