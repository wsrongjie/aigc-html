# 资产检索入口调整实施计划

目标：将「全部资产」收敛为跨系统资产检索入口，减少与侧栏分类入口的重复。

授权：用户已确认前一轮方案，并要求「改一版看看效果」。本计划落盘后直接执行，不重复申请确认。

实现：保留单文件 HTML/CSS/原生 JavaScript、稳定资产 ID 和既有数据。为检索页单独增加紧凑筛选布局，复用现有结果列表、详情、导出和分页，不调整其他分类页的信息架构。沿用现有深蓝侧栏和蓝色主色。

## 修改文件

- `企业数据资产中心-交互原型.html`：入口命名、检索布局、组合条件、搜索入口衔接。
- `tests/asset-center.spec.py`：入口名称预期更新。
- `tests/asset-search.spec.py`：组合筛选、导出范围、重置、隐藏条件提示、中文组合输入、窄屏及回归验证。
- `outputs/asset-center/原型查看说明.md`、`outputs/asset-center/企业数据资产中心-原型包.zip`：同步查看指引和交付包。
- `outputs/asset-center/search/`：独立浏览器验证报告及截图。

## 执行步骤

1. 保存调整前的首屏截图与原型哈希。
2. 将所有菜单、面包屑和移动入口中的「全部资产」改为「资产检索」；保持内部 page ID 为 all。
3. 检索页移除四张全库统计卡和类型标签，默认列表；类型、来源、记录日期放在基础筛选。
4. 更多筛选提供客户、销售、文件形式，按稳定 ID 关联匹配；折叠后继续展示已选条件并支持单项移除。重置与切换菜单清空这些条件。
5. 当前匹配数量、列表、分页和导出使用同一筛选结果；全局搜索回到检索页并带入关键词。
6. 保护中文组合输入过程，避免检索重绘打断输入；确保筛选按钮和选择器重绘后焦点可恢复。
7. 运行既有浏览器回归和新增定向验证，检查 1440、1280、900、390、320 像素布局并查看截图。
8. 按项目要求进行多 Agent 对抗性只读审查，修复本次引入的问题后复验；更新说明和分享包。

## 约束与风险

- 本次聚焦入口和检索交互，不批量处理之前评审的其他问题。
- `pageAssets`、`matches` 和输入事件被多个页面共用，新关联筛选仅在 all 页面生效；回归营销素材、日期聊天及人员档案。
- 日期匹配资产自身记录时间；客户与销售按资产关联关系筛选，不推断一次具体发送。页面提示用户进入关联记录查阅发送对象与时间。
- 客户、销售等关系沿用稳定 ID，不复制资产、不新增虚构会话、不回写客户系统。
- 浏览器使用独立临时上下文，不操作用户已有浏览器，不修改客户资料和既有备份，不执行 Git 操作。
- 浏览器 IME 通过 Chromium 组合事件验证，不能替代 Windows 原生输入法的人工验收。

## 验收标准

- 检索页不存在类型标签和全库统计卡，首屏可以直接检索及查看结果。
- 组合筛选与导出范围一致；收起更多筛选时有效条件仍可见、可移除。
- 切换其他菜单不继承检索页的客户、销售、文件形式条件。
- 顶栏搜索转入资产检索；中文组合输入不产生拼音残留；其他页面原有入口可用。
- 直接打开 HTML 可用，原有备份哈希保持不变，浏览器无脚本、控制台和资源请求错误。

## 执行结果

- 已完成入口改名、移除检索页统计和分类标签、基础与高级组合筛选、条件提示及单项移除、默认列表、全局搜索衔接。
- 检索结果、匹配数量、分页与导出继续共用同一筛选结果。日期和关联筛选边界已在页面注明。
- 中文组合输入增加组合阶段保护；选择器和筛选按钮重绘后恢复焦点。
- 既有浏览器回归 74 项通过，新增资产检索检查 28 项通过；两轮独立 Agent 审查未发现本次引入的可复现问题，其中数据与布局审查另有 39 项只读检查。
- 已人工查看桌面组合检索、1280×720 首屏、390 像素展开布局截图；程序检查覆盖 1440、1280、900、390、320 像素，均无整页横向溢出。
- 报告：`outputs/asset-center/verification.json`、`outputs/asset-center/search/verification.json`、`outputs/asset-center/search/boundary-review.json`、`outputs/asset-center/search/evidence-review.json`。
- 截图：`outputs/asset-center/search/01-调整前.png` 至 `07-资产检索-窄屏展开.png`。查看说明及分享包已同步更新。
- 既有备份哈希未变；无 Git 操作。Windows 原生输入法、客户生产系统及真实设备未验收。
