# 企微质检全链路原型（2026-10-24）

> 目标：把「数据接入 → 质检规则 → 质检模型 → 质检计划 → 质检结果复核」主链，与「营销素材质检（含申诉终审）」「文字直播间实时告警」两条业务链路，做成一个可点通、可评审的单文件原型。
>
> 交付物：`风控质检-交互原型.html`（重构，1200 行）、`docs/prd/风控质检SaaS-产品需求文档.md` 第 12 章、`index.html` 入口更新。

## 1. 范围与不做什么

**做**

- 8 个模块、22 个可见视图，全部可交互（筛选、详情、状态流转、弹窗）。
- 质检场景 / 规则 / 模型 / 计划的分层关系，和「配置边界」。
- 复核策略四选一（全部人工 / 低于阈值 / 抽检 / 免复核）及阈值语义。
- 素材质检完整闭环：发起 → 结果 → 修改重审（版本链）→ 申诉 → 终审。
- 直播间实时告警：意图识别 → 销售归属 → 响应/升级 → 转质检结果。
- 运行批次漏斗与失败明细（可解释性）。

**不做**

- 不接后端、不做真实模型调用；数据全部虚构，仅用于交互评审。
- 不做权限矩阵的实际拦截（仅展示角色定义）。
- 不做报表数字自洽（结构与口径为主）。
- 不替代客户现有合规系统的授权流程（AI 结论仅为建议）。

## 3. 状态机

**质检结果（销售话术）**

```text
待复核 → 待处置 → 待结案 → 已结案
  ├→ 已关闭（误报）
  └→ 证据不足
```

**营销素材**

```text
不通过 → （修改重审 vN）→ 通过
不通过 → 申诉中 → 终审通过 / 终审不通过
```

**直播告警**

```text
待响应 → 已响应
待响应 → 已升级（主任/合规）
任意状态 → 转为质检结果
```

## 4. 关键设计决策

1. **术语统一为「质检」**：规则 / 模型 / 计划 / 结果；「风控」只作品类词。
2. **模型与计划分离**：模型不感知渠道与时间，计划承担范围、频率、复核策略。
3. **复核阈值语义**：`置信度 < X%` 转人工（非风险分），阈值在计划级覆盖模型默认值。
4. **素材结论可申诉**：AI 结论为建议，终审由合规完成；改判样本回流测试集。
5. **告警与结论分离**：直播间告警是信号，转质检结果后才进入复核。
6. **证据不足是独立终态**：不输出风险结论，不计入召回率分母。

## 5. 模拟逻辑说明（演示可信度）

- 素材质检用关键词规则模拟模型：承诺收益 / 历史业绩 / 诱导退费 / 极限词 / 操作指令 → 生成风险点与得分。
- 规则试跑按正例 / 反例做包含匹配，输出「命中 / 不命中 / 证据不足」。
- 其余数字为静态样例，口径与字段真实，数值不对应真实业务。
