### 0.3 沿用的既定决策（不在本文重新讨论）

1. 规则为「风险领域 → 风险主题 → 原子规则 → 场景策略」四层；
2. 首期规则中心只开放语义规则，关键词只作为模型内部召回特征；
3. 模型只管规则组合、敏感度、测试与发布，不管数据来源、范围、时点、通知；
4. 计划管数据来源、范围、时点、通知与时限；
5. AI 只输出「疑似风险 + 证据 + 建议」，不下违规结论、不处罚、不退款、不拦截；
6. 模型发布采用混合门槛：技术验证失败阻断，业务指标不达标强提醒+留痕放行。

## 1. 产品定义

### 1.1 一句话

在投顾类机构的企微沟通、营销素材与直播三类内容上，用「规则 + 大模型」做语义级风险判定，把海量误报收敛成**少量高确定性的风险事件**，并给出可直接核验的证据链与处置闭环。

### 1.2 它替代什么、不替代什么

| 替代 | 不替代 |
| --- | --- |
| 纯敏感词/正则触发的告警与人工逐条筛查 | 会话存档、订单、合同、呼叫中心等源系统 |
| 跨系统手工拼证据（合规系统 → 订单系统 → 聊天记录） | 原合规系统的任务与审核流程（首期通过接口复用） |
| 群聊喊「过 / 不过」的素材审核留痕方式 | 企微群本身（群内快捷审核是入口，不是被替代对象） |

### 1.3 买方与验收线（决定产品取舍）

甲方内部至少三条验收线，诉求并不完全一致，产品必须显式对齐：

| 角色 | 关心什么 | 对应验收 | 访谈依据 |
| --- | --- | --- | --- |
| 老板 / 总经理 | 投诉率、退款率、人力成本 | 指标环比下降 | 沈老师转述老板诉求；合规访谈"先把客户投诉降下来" |
| 合规负责人 | 判得准、能解释、能追溯、制度能落地 | 误报率、取证耗时、结案时效 | 合规访谈"精准优先，131 条也能接受" |
| 产品 / 技术 | 集成成本、可维护、可迭代 | 接口数量、权限一致性、模型可配置 | 产品团队访谈"更关注评测数据" |

**产品取舍原则**：以「精准」作为上线闸门（不达标不上线、不铺量），以老板指标作为最终价值证明，以技术集成成本控制交付风险。三者冲突时，先保精准，再保范围。

### 1.4 产品定位边界（写给甲方的一句话）

> 我们不是替换你们的合规系统，而是在它前面加一层"会看语境的判断层"，并把它散落在各系统里的证据自动拼好。

## 3. 核心业务链路

### 3.1 链路 A：企微聊天 T-1 风控（P0 主线）

```text
计划调度（每日固定时点）
  → 拉取前一天会话（文字/语音转写/图片OCR）
  → 标准化内容对象（含客户、员工、产品、订单关联）
  → 一级召回：词库 + 规则特征（低成本，全量）
  → 二级筛选：小模型意图打分（投诉/退费/抱怨/外诉）
  → 三级判定：大模型结合规则做语境判定 + 证据定位
  → 生成风险信号（不直接生成任务）
  → 按客户+主题+责任人+时间窗聚合为风险事件
  → 合规复核（误判/成立/证据不足）
  → 生成处置任务 → 通知销售/主任
  → 销售处理并提交 → 合规复核 → 结案 / 逾期 / 延期
  → 结论回流评测集
```

**为什么必须三级漏斗**：甲方日增约百万级条沟通记录、存量违规触发约 180 万条。全量直接过大模型在成本和时延上都不可行，也会重现"全判违规"的失败。一级召回求全，二三级求准。

### 3.2 链路 B：素材发布前预审（P0 第二条）

```text
策划/业务提交素材（平台提交 或 群内快捷提交）
  → AI 预审：通过 / 修改后通过 / 不通过 + 风险位置 + 改写建议
  → 合规人工决定（AI 建议不构成最终结论）
  → 结果留痕并通知提交人
  → 是否阻断发布由原业务系统决定（我方不阻断）
```

**关键约束（来自访谈）**：素材审核现在走企微群，原因是"群里快、周末也在"。因此**不能强行把审核迁到平台**，必须提供群内快捷入口（引用消息 → 生成审核单 → 回复结论 → 平台留痕），平台作为留痕与统计的权威源。

### 3.3 链路 C：直播事后审查（P1）

场次登记 → 录像/评论拉取 → 转写与画面描述 → 风险点定位（时间轴）→ 生成事件 → 复核。不中断直播。

### 3.4 链路 D：客诉/退款处置（P0 与 A 共用）

事件定级 → 设定处理时限 → 通知销售与主任 → 销售安抚或走退款 → 合规核实退款状态与二次情绪 → 结案。
系统需支持访谈中明确的机制：**同一客户重复触发计数、400 电话计数、工作日超时判定**，并输出"建议强制介入"提示（不自动执行）。

## 5. 关键功能需求

### 5.1 规则中心

- 四层结构、原子规则字段、版本生命周期沿用既定设计；
- 首期只开放语义规则，**不提供用户可配置的关键词/正则/词典规则**；
- 每条规则必须可回答：判什么、什么不算、要什么证据、AI 允许输出什么；
- 规则的严重度基准不随模型敏感度变化；
- 规则被引用后不可原地修改，只能发新版本；历史结果保留当时快照。

**验收**：任一线上风险事件可精确回溯到「规则 + 规则版本 + 模型版本 + 计划批次」。

### 5.2 模型中心

- 模型绑定规则时固定规则版本，可设置敏感度覆盖、置信度门槛、是否必复核、展示优先级；
- 五步流程与五状态沿用既定设计；
- 测试必须冻结快照（模型版本 + 规则版本 + 测试集版本 + 敏感度 + 上下文配置 + 底层能力版本）；
- 已发布不可覆盖，改则生成新版本并保留历史快照。

### 5.3 计划与运行（本次新增设计）

| 配置项 | 说明 |
| --- | --- |
| 场景与数据源 | 企微聊天 / 素材送审 / 直播录像 / 外呼录音 |
| 运行范围 | 组织、团队、员工、企微账号、产品线；支持排除名单 |
| 运行时点 | T-1 固定时点、素材实时、直播结束后 N 分钟；需支持业务日/自然日定义 |
| 绑定模型 | 指定模型版本（不随模型更新自动升级，避免不可预期漂移） |
| 识别档位 | 计划级可覆盖模型默认敏感度（对应行情松紧） |
| 通知与时限 | 通知对象、首响时限、处理时限（工作日）、升级链、逾期动作 |
| 输出粒度 | 仅信号 / 直接生成事件 / 需人工确认后生成任务 |
| 失败策略 | 局部重试、降级为词库命中、批次熔断 |

**批次必须记录**：拉取量、去重量、召回量、筛选量、判定量、事件数、失败数、耗时、token 成本、模型与规则版本快照。批次详情要能回答"这一批为什么少了 30%"。

### 5.4 运行链路与成本控制

- 标准化内容对象（沿用既定协议）：原文/转写、图片 OCR 与描述、主体与对象、时间、前后文、来源与回跳、业务事实、数据质量标记；
- 三级漏斗：词库与规则特征（全量）→ 小模型意图打分（候选）→ 大模型语境判定（高价值候选）；
- **成本指标必须产品化**：批次详情展示单条成本与各阶段占比，支持按场景设预算阈值与降级策略；
- 降级原则：数据缺失或转写质量低时，不输出风险结论，输出「证据不足」并标记原因，不得推测。

### 5.5 事件聚合与复发

聚合维度：稳定客户 ID + 风险主题 + 责任对象（员工/素材/直播/订单）+ 时间窗。

- 同客户同日"退款"与"举报另一销售违规"**不合并**；
- 同客户围绕同一亏损问题的连续抱怨**可聚合为一个事件**并保留每次触发；
- 支持授权人员拆分、合并、撤销合并并记录原因；
- 复发计数独立于事件状态，用于 3 次 / 400 三次 / 3 工作日规则。

### 5.6 统一事件详情（首期最重要的一页）

一屏内必须同时给出：

1. **结论区**：AI 分析结果、命中规则与版本、置信度、AI 建议等级、人工判定、事件生命周期、任务状态、复发关系（七维分列，不合并）；
2. **证据区**：原始消息/素材片段（高亮）、上下文、语音转写与情绪曲线（如有）、关联订单/退款/合同状态及来源更新时间、回跳按钮、缺失或无权访问标记；
3. **处置区**：任务、责任人、时限、销售提交内容、处理历史；
4. **历史区**：同客户历史事件、同员工历史违规、同素材历史审核。

**验收**：合规人员从打开事件到形成判断，不需要切到其他系统；若必须切，跳转后能一键返回并保留上下文。

### 5.7 复核、任务与时限

| 状态维度 | 取值 |
| --- | --- |
| AI 分析结果 | 未分析、疑似风险、未发现风险、分析失败、证据不足 |
| 人工判定 | 未判定、误判、风险成立、确认违规、证据不足、无法判断 |
| 事件生命周期 | 新发现、待复核、已确认、处置中、观察中、已关闭 |
| 任务状态 | 待领取、待处理、处理中、待复核结案、已完成、延期、逾期、取消 |
| 复发关系 | 首次事件、关联历史、复发、合并、拆分 |
| 素材审核决定 | 待审核、通过、修改后通过、不通过、退回修改 |

- 误判事件也必须正常关闭并留痕，不允许"删掉"；
- 延期需填原因与新时限，计入延期统计；
- 逾期触发升级通知，但不自动升级处罚；
- 强制介入（退费）只输出**建议**，由授权人员决定。

### 5.8 素材预审

- 输出三档结论（通过 / 修改后通过 / 不通过）+ 风险位置 + **改写建议（保持原意）**；
- 尺度按产品线（1.0/2.0/3.0 价位与产品特性）与素材类型分别配置；
- 必须支持"同一标题单独看可过、加上个股验证/盈利截图就要卡"这类组合判断；
- 必须能识别过度渲染信号（图标、金元宝、火箭、箭头、涨停红框黄字、字号强调）——首期可作为规则+OCR+视觉提示，不承诺全覆盖；
- 群内快捷审核为 P1，但**必须在方案中承诺**，否则客户不会迁出群聊。

### 5.9 客户风险与员工质检

- 客户风险：等级、标签、拦截建议与解除记录；等级调整必须填理由；
- 员工质检：确认违规结论、整改说明、罚单草稿、签收与报送状态；人事扣款与培训在我方系统外完成，只做状态记录与导出；
- 两者都只做"记录 + 建议"，执行动作留在原系统。

### 5.10 评测与回流

- 人工的每一次「误判/成立/分类修正/证据选择/结案原因」都要成为可训练数据；
- 测试集支持预置、客户上传、从历史复核沉淀；
- 指标：准确率、召回、误报、漏报、证据完整率、运行失败率、平均取证时长、平均处置时长；
- **双轨静默评测**为一期验收方式：先只跑不告警，与人工结论比对达标后再开告警。

### 5.11 通知（不打扰原则）

- 默认只通知"需要动作"的人，不做全量抄送；
- 销售侧任务通知必须包含：客户、问题摘要、要求、时限、一键入口；
- 支持免打扰时段与批量摘要（例如每日一次汇总），避免重现"一天几十条提醒，销售直接无视"。

## 7. 集成与部署

### 7.1 部署形态

- 甲方阿里云内网私有化部署，数据不出内网；
- 代码按单租户交付，架构**预留多租户**（未来 SaaS 化不改核心表结构）；
- 三要素（姓名、手机号、身份证）不进入我方存储；如需传输，先过客户内网的脱敏小模型；
- 算力与 token 结算方式待商务确认，产品侧必须先支持按场景设预算与降级。

### 7.2 接口清单（初稿）

| 方向 | 用途 | 频率 | 失败处理 |
| --- | --- | --- | --- |
| 入 | 会话存档增量（文字/语音/图片） | 5 分钟内 | 断点续拉、缺失告警 |
| 入 | 组织架构与员工账号映射 | 每日/变更触发 | 保留上次快照 |
| 入 | 订单、退款、合同、服务状态（只读） | 准实时/按需 | 标注数据时点，不缓存为真相 |
| 入 | 素材送审与版本 | 事件触发 | 重试 + 人工补录 |
| 入 | 直播场次、录像、评论 | 场次结束后 | 缺口登记 |
| 出 | 任务创建/更新（优先写回原系统） | 事件触发 | 幂等 + 对账 |
| 出 | 复核结论与标签回流 | 事件触发 | 幂等 |
| 出 | 通知（企微应用消息） | 事件触发 | 重试 + 站内兜底 |

### 7.3 与原系统、资产中心的边界

沿用既定职责表，落地要点：

- 不复制业务真相：订单、退款、合同状态以源系统为准，我方只存索引与快照时点；
- 不丢来源：每条 AI 结论必须能回跳到原始记录；
- 不绕过权限：新页面可见范围 ≤ 来源系统；
- 不让 AI 定责；
- 优先回写原任务，避免第二套状态机。

**若原系统状态机验证不通过，必须在架构评审时先定"任务主存"，再开发工作视图**——这是本项目最容易翻车的地方。

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 权限 | 行级 + 字段级；导出单独授权；越权访问有审计 |
| 审计 | 查看、导出、判定、改规则、改模型、改计划全量留痕，不少于监管要求期限 |
| 性能 | T-1 批次在次日 9:00 前出结果；素材预审 P95 ≤ 60 秒；详情页首屏 ≤ 2 秒 |
| 可用性 | 单批次失败不影响其他计划；支持熔断与重跑 |
| 可解释 | 任一结论可展开到规则、版本、证据、模型判断依据；不允"黑盒结论" |
| 数据质量 | 转写质量、缺失、过期必须显式标注，不得静默当成有效证据 |
| 成本 | 单条判定成本可观测；支持按场景预算与降级 |
| 安全 | 内网部署、脱敏、密钥托管、日志脱敏 |

## 9. 验收与效果指标

### 9.1 技术验收（上线闸门）

- 三条链路端到端跑通，批次可追溯；
- 事件 → 证据 → 规则 → 模型 → 批次的回溯链完整率 ≥ 99%；
- 运行失败率 ≤ 1%，失败可定位、可重跑；
- 权限与审计通过抽检。

### 9.2 效果验收（建议基线，需与甲方确认后写入合同）

| 场景 | 指标 | 建议基线 |
| --- | --- | --- |
| 企微 T-1 外诉/投诉 | 高危样本召回 | ≥ 95% |
| 企微 T-1 外诉/投诉 | 高危样本精确率 | ≥ 80% |
| 企微 T-1 退费意图 | 精确率 | ≥ 70% |
| 素材预审 | 与人工结论一致率 | ≥ 85% |
| 全部场景 | 证据完整率 | ≥ 95% |
| 全部场景 | 单事件取证耗时 | 下降 ≥ 50% |

**说明**：以上为产品建议值，不是承诺值。签约前需用甲方真实脱敏样本做一次小规模盲测，用盲测结果校准基线，再写入验收条款。不做盲测直接承诺指标是本项目最大的商业风险。

### 9.3 业务验收

投诉率、退款率、合规人均处理量、平均结案时长、逾期率、无效任务量。需要甲方提供上线前 3 个月基线。

### 9.4 验收方式

**双轨静默运行 2–4 周**：系统只出结论不告警，与人工判定逐条比对，达标后开告警。这是降低"上线即翻车"的最有效手段，也便于向老板证明效果。

## 11. 待确认与风险

### 11.1 必须由甲方确认（阻塞开发）

1. 原咨诉/违规状态机能否作为唯一任务主存，能否开放接口；

7. 行情松紧档位由谁决定、多久调整一次（对应计划级敏感度）。

### 11.2 产品侧待验证

1. 企微群内快捷审核的技术可行性（会话存档 + 群机器人 + 回复解析）；
2. 语音转写质量与情绪特征的可用性；
3. 直播评论与录像采集覆盖率；
4. 图片中"过度渲染"信号的识别边界；
5. 单条判定成本能否落在客户可接受区间。

### 11.3 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型效果不达预期 | 验收失败、尾款风险 | 先盲测再承诺；双轨静默；按类别逐步放开 |
| 主数据关联不成立 | 证据链断裂，产品价值归零 | 一期前置做映射验证，作为 Go/No-Go 条件 |
| 原系统不配合 | 变成第二套孤岛 | 架构评审先定任务主存；提供只读过渡方案 |

| 合规尺度争议（总部 vs 本地） | 规则谁定说不清 | 规则与计划分离；计划级敏感度；操作留痕；不做内部审批流 |
| 成本超支 | 毛利被吃掉 | 三级漏斗 + 批次成本可视化 + 预算降级 |

## 12. 全链路质检设计（2026-10-24 增补）

本章按客户 2026-10-24 的口径重构：**主动拉数 → 质检规则 → 质检模型 → 质检计划 → 质检复核 → 申诉终审 → 质检报表**，并覆盖营销素材质检与文字直播间实时告警两条独立业务链路。

### 12.1 术语与定位

- 产品名统一为「**质检**」；对外品类仍可称「风控质检」，「风控」不作为模块名。
- 三个判定对象：**内容合规**（素材/话术/直播）、**员工行为**（违规话术/服务态度）、**客户意图**（投诉/退款/抱怨）。
- 两条结论线必须在界面上分栏，禁止合并：

| 结论线 | 判什么 | 依据 | 责任方 | 是否阻断 |
| --- | --- | --- | --- | --- |
| 合规结论 | 能不能发 / 能不能成交 | 监管红线、总部制度、公司尺度 | 合规 | 是（授权人工决定） |
| 内容质量结论 | 做得对不对、好不好 | 盘面事实、产品口径、SOP、审美 | 运营/策划 | 否（自检，可重做） |

> 客户原话：「合规会检查，但合规不会检查内容的对与错。」错别字、数据过期不得判定为合规违规，否则会污染尺度校准。

### 12.2 模块与页面（新 IA）

```text
AI 质检工作台
  ├─ 质检看板
  └─ 质检复核（统一复核工作台，按渠道分三个二级菜单）
       ├─ 企微消息复核
       ├─ 营销素材复核
       └─ 文字直播间复核
质检配置
  ├─ 质检规则（含风险类型字段）
  ├─ 质检模型
  └─ 质检计划
质量与报表
  ├─ 素材质检申诉
  ├─ 质检报表
  └─ 系统配置（数据接入 / 角色权限 / 通知规则 / 组织与账号映射 / 审计日志）
```

> **2026-10-24 三次收敛**：撤销「业务入口」组。质检任务统一由质检计划下发（素材送检 = 计划 P-1003 手动触发；直播 = 计划 P-1004 实时流），结果统一在质检复核的三个渠道展示。原「营销素材质检」「文字直播间监控」两个列表页删除，其详情页保留为复核下钻页（面包屑挂在质检复核下）。最终导航 8 项。
>
> **2026-10-24 二次收敛**：导航从 12 项收到 10 项。「我的待办」首期不做（销售整改任务在质检复核的处置动作中闭环，待终审申诉在素材质检申诉页处理）；「数据接入」从质检配置下移进系统配置，避免把"接得通"与"判得准"混在同一组。质检配置只留 规则 → 模型 → 计划 三步主干。

| 模块 | 核心职责 | 不放什么 |
| --- | --- | --- |
| 数据接入（系统配置内） | 拉取、水位线、补采、失败重试 | 不做判定 |
| 质检规则 | 原子判定单元、风险类型、正反例、证据要求 | 不含渠道、运行范围 |
| 质检模型 | 规则组合 + 敏感度 + 置信度阈值 + 素材类型 + 规则启停 | 不含数据来源、执行时间、复核策略 |
| 质检计划 | 数据范围、频率、窗口、复核策略、结果去向、时限 | 不改规则内容 |
| 质检复核（原质检结果） | 三个渠道统一复核：结果队列、证据、结论、处置闭环 | 不做模型训练；不替代业务入口的发起与实时响应 |
| └ 企微消息复核 | 单聊原文、命中片段、处置流转 | 不含素材与直播 |
| └ 营销素材复核 | 素材原文高亮、命中位置、改写建议、申诉终审 | 不替代合规群发布授权 |
| └ 文字直播间复核 | 评论流窗口、建议话术、转质检结果 | 告警不等于违规结论 |
| 素材质检申诉 | 不认可 AI 结论 → 合规终审 → 维持 / 改判 | 不替代合规群最终授权 |

### 12.3 数据接入（系统配置 · 主动拉取）

> 入口调整：数据接入不再作为质检配置下的一级菜单，改为「系统配置」的第一个 tab；数据源详情页保留，面包屑为「系统配置 / 数据接入 / 数据源详情」，侧栏系统配置项显示异常数据源数徽标。

| 项 | 设计要求 |
| --- | --- |
| 拉取方式 | **pull 为主**：会话存档按 seq 增量、通话按时间窗、素材按提交触发、直播评论按实时流；push 仅作为触发信号，不作为数据源 |
| 状态可见 | 水位线、延迟、今日拉取量、失败率、最近拉取时间、缺口区间 |
| 补采 | 支持按时间区间手动补采，生成独立批次并标注来源；失败数据不进入召回率分母 |
| 前置条件 | **员工主档 ↔ 企微账号 mapping**（一人多号、账号名不一致）；以钉钉组织架构为主数据，10 天全量 + 每日增量 |
| 数据源清单 | 企微会话存档、呼叫中心通话、文字直播间评论流、营销素材库、订单与退款（证据用） |
| 标准化 | 原文/转写、图片 OCR、主体与对象、时间、前后文、来源回跳、业务事实、数据质量标记 |

失败策略：局部重试 3 次 → 降级为词库命中 → 批次熔断并告警；数据缺失或转写质量低时输出「证据不足」，不得推测。

### 12.4 质检规则（含风险类型字段）

**单层结构**：不再设独立「质检场景」模块。风险类型作为规则上的**固定枚举字段**，用于规则分类、结果筛选与报表分组；客户说「先做违规承诺收益这一类」时，指的就是这个字段。

风险类型枚举（不可由用户新增）：违规承诺收益、违规指导操作、夸大宣传与极限词、诱导退费、保证效果与兜底、投诉意图、退款意图、亏损抱怨与情绪、辱骂与服务态度、适当性与超范围荐股。

| 规则字段 | 要求 |
| --- | --- |
| 编号 / 名称 | 一条规则只判一件事 |
| 风险类型 | 必填，单选，固定枚举 |
| 严重度 | L0 立即 / L1 复核 / L2 仅记录 |
| 判什么 | 必填；描述必须同时满足的条件 |
| 什么不算 | 必填；列出易误判情形（否定句、引用监管材料、客观事实） |
| 证据要求 | 原文 / 上下文 N 条 / 语音 / 图片 OCR / 订单退款状态 / 素材包整体 |
| 允许输出 | 命中 / 不命中 / 证据不足（禁止推测） |
| 正反例 | 各 ≥ 2 条，用于蒸馏与回归 |
| 版本 | 被模型引用后不可原地修改，只能发新版 |

硬约束：首期只开放语义规则，不提供用户可配置的关键词 / 正则 / 词典规则；关键词仅作高召回前置，不作结论。

### 12.5 质检模型

模型 = **规则组合（冻结版本）+ 敏感度 + 每规则置信度门槛 + 素材类型 + 规则启停**，按业务场景命名，不感知渠道。是否人工复核不在模型配置。

| 模型示例 | 绑定规则 | 使用方式 |
| --- | --- | --- |
| 销售营销话术质检模型 | 承诺收益 / 历史业绩暗示 / 操作指令 / 兜底 / 辱骂 | T-1 全量扫销售沟通 |
| 营销素材审核模型 | 夸大宣传 / 极限词 / 诱导退费 / 组合式高预期 / 版本一致性 | 素材发布前预审 |
| 直播间客户意图模型 | 投诉意图 / 退款意图 / 亏损抱怨 | 实时评论流 |
| 客户咨诉识别模型 | 外诉 / 内诉 / 退费 / 抱怨 | 客诉事后归集 |

- **质检素材类型（模型级，多选）**：文本 / 图片 / 音频 / 视频。模型只能质检已启用的素材类型；类型决定测试验证的输入形态与识别链路（文本→语义判定，图片→OCR+视觉，音频→ASR+情绪，视频→抽帧+转写）。内置建议：销售话术=文本+音频；素材审核=文本+图片+视频；直播间=文本+音频；客诉=文本+音频。
- **分类型测试验证**：第 4 步先选素材类型（未启用的置灰），文本直接粘贴聊天记录，图片/音频/视频上传附件并填写 OCR / 转写文本。附件仅本地预览、不做真实解析；识别文本为空时判定为「证据不足」，不计为有效测试，不允许进入发布确认。
- **规则启停**：模型内每条绑定规则可独立启用/停用；停用规则不参与测试与计划运行，历史结果不受影响；已发布版本需通过新版本变更启停状态。
- **发布检查清单**：基础信息、素材类型、规则（至少 1 条启用）、复核策略、有效测试（证据不足不计）、输出结构共 6 项；任一项未完成则发布按钮禁用；版本说明必填，进入版本记录与审计日志。
- **结构化输出（固定 Schema，只读）**：`risk_level` / `score` / `findings[]`（`rule_id`、`rule_name`、`evidence`、`confidence`、`span`）/ `review_required` / `material_type` / `model_version`；证据不足时 `risk_level=null` 并输出 `reason`。测试页右侧展示 JSON、耗时、Token 与证据位置。
- **组合判定**：单条通过但「主标 + 个股验证 + 收益渲染」组合违规，按素材包整体判定（对应 R-012）。
- **发布门槛**：技术验证必须通过；准确率/误报率未达标时允许带风险发布，但必须填写原因并留痕。
- 测试必须冻结：模型版本 + 规则版本 + 测试集版本 + 敏感度 + 上下文配置。

### 12.6 质检计划（质检任务）

| 配置区 | 字段 |
| --- | --- |
| 基本信息 | 计划名、业务类型、绑定模型版本（**不自动随模型升级**） |
| 数据范围 | 组织 / 团队 / 员工 / 企微账号 / 产品线（1.0/2.0/3.0）、排除名单 |
| 运行频率 | **T-1 每日固定时点** / 每小时 / 实时流 / 手动触发；业务日或自然日 |
| 数据窗口 | 如 T-1 00:00–24:00，跨天消息按会话归属日归集 |
| **复核策略** | ① 全部人工复核 ② 置信度低于阈值 X% 转人工 ③ 按比例抽检 N% ④ 免复核直接处置 |
| 结果去向 | 生成结果 / 自动派单销售 / 通知主任 / 返回运营 / 进入申诉池 |
| 时限与升级 | 首响时限、处理时限（工作日）、逾期升级链、强制介入条件 |
| 失败策略 | 局部重试、降级词库、批次熔断 |

阈值语义（已按此实现）：**置信度 < X% 才转人工**；高于阈值可直接生成处置任务。免复核仅用于实时告警类场景，且需模型稳定在目标线以上。

复核策略的**唯一配置入口是质检计划**，模型只提供敏感度与每条规则的置信度门槛；避免同一策略在两个对象上重复配置、互相覆盖。

数据源与素材类型匹配：计划选择模型后，系统需提示该模型支持的素材类型；若计划对应的数据源（如素材图片）不在模型启用范围内，给出黄色提示而非硬性阻断，由配置人确认。

批次必须可解释：`拉取 → 去重 → 词库召回 → 小模型候选 → 大模型判定 → 结果 → 失败`，并记录耗时与 token 成本。

### 12.7 质检复核（原「质检结果」）与人工复核

**三个渠道共用一个复核工作台**，页面右上角渠道切换与左侧二级菜单等价；不建三套页面，避免三套结论状态机。

| 渠道 | 取数 | 队列口径 | 人工动作 |
| --- | --- | --- | --- |
| 企微消息复核 | 质检结果（销售与客户单聊） | 待复核 5 条 | 确认违规 / 判定误报 / 证据不足 / 转派整改 |
| 营销素材复核 | 营销素材质检单 | 不通过 1 + 申诉待终审 1 | 认同一审 / 判定通过 / 退回修改 / 维持原判 / 改判通过 |
| 文字直播间复核 | 直播告警 | 待响应 + 已升级 | 转质检结果 / 升级主任 / 标记误报 |

- 右栏结构三条渠道一致：AI 提示卡（等级、置信度、命中规则）+ 人工结论卡（独立状态）+ 判断依据 + 关键证据 + 边界说明；
- 中栏按渠道换证据面：会话流 / 素材原文高亮 + 命中位置 + 改写建议 / 直播评论流 + 判定窗口；
- 不再设「业务入口」菜单：任务由质检计划下发，结果只在复核侧出现，避免同一批数据两套入口；素材送检在计划 P-1003 手动触发，直播告警由计划 P-1004 实时流产生。


结果状态机（严格五态，不混用）：

```text
待复核 ──确认违规──→ 待处置 ──销售处理提交──→ 待结案 ──复核通过──→ 已结案
   │                    │                        │
   ├─误报关闭─→ 已关闭   ├─逾期─→ 逾期升级        └─退回─→ 待处置
   └─证据不足─→ 证据不足（不生成任务）
```

结果页为**三栏复核工作台**，参照内部「风险复核」原型的信息结构，取消"列表 + 独立详情页"两套界面：

| 区域 | 内容 | 设计约束 |
| --- | --- | --- |
| 概览条 | 待人工复核数、其中 L0 数、待处置/待结案/已闭合/证据不足 | 数字随筛选联动，一眼看出待办压力 |
| 左：结果队列 | 等级 + 状态 + 摘要 + 销售→客户·团队 + 命中规则 + 时间/置信度 | 支持高风险优先 / 时限最近 / 最新入队 |
| 中：原始会话 | 气泡流、命中片段高亮、消息 ID、AI 命中标注条 | 证据必须可定位；只读 |
| 右：复核详情 | AI 提示卡（疑似等级 + 命中规则 + 「最终认定以人工结论为准」）→ 人工结论卡 → 判断依据 → 关键证据引用 → 命中规则折叠 → 证据元数据（业务事实、计划、时间、消息 ID）→ 边界说明 | AI 提示与人工结论必须分区，不得混写 |
| 右：处理轨迹 | 模型生成 → 进入队列 → 人工结论 时间线 | 与复核详情共用右栏，tab 切换 |
| 底部固定区 | 确认违规 / 判定误报 / 证据不足 / 转派整改 + 上一条/下一条 | 常驻，不需滚动到底 |

**不设批量复核**：复核必须逐条看原文，批量勾选会诱导"不看证据直接确认"；导出能力保留。

复核结论回流训练集，并用于规则尺度校准。

### 12.8 营销素材质检（任务由计划下发）

> 入口调整：原「营销素材质检」列表页与「发起质检」页已下线。送检由计划 P-1003「营销素材发布前预审 · 手动触发 · 提交即检」下发；结果在「质检复核 · 营销素材复核」处理；质检单详情作为复核下钻页保留。

```text
运营发起（选素材/上传 → 选模型 → 提交）
        ↓
   即时质检
   ├─ 通过 → 可发布（留档）
   └─ 不通过
        ├─ 运营认可 → 修改 → 提交 v2 → 重审 → …直到通过
        └─ 运营不认可 → 申诉 → 专业审核人员终审
                              ├─ 维持不通过 → 必须修改后重审
                              └─ 改判通过 → 可发布，样本回流
```

- **版本链必须连续**：v2 挂 v1，可查看每条建议是否被采纳；每次修改生成新版本并保留历史。
- **风险定位**：文字划选高亮、图片区域 + OCR 文本、视频时间点。
- **建议改写稿**：不通过时同时给出可直接采用的改写版本。
- 与合规「素材群审核」并存：本模块是发布前预审闸门，**AI 结论为建议，最终授权仍由合规审核人决定**。
- 申诉期间素材不得发布；终审为一次性结论，需记录终审人、依据与时间。

### 12.9 文字直播间实时告警

> 入口调整：原「文字直播间监控」列表页已下线。告警由计划 P-1004 实时流产生，结果在「质检复核 · 文字直播间复核」处理；告警详情作为复核下钻页保留。

链路：`评论流 → 意图识别（退款/投诉/亏损抱怨）→ 客户 ID → 服务关系映射 → 定位当前销售 → 告警`

| 项 | 设计 |
| --- | --- |
| 触发 | 命中意图规则且置信度 ≥ 计划阈值 |
| 收敛 | 同一客户 10 分钟内合并为一条，避免刷屏 |
| 送达 | 企微应用直发服务销售，抄送主任 |
| 内容 | 原句 + 上下文 + 风险类型 + 建议安抚话术 + 一键跳转客户档案 |
| 升级 | 10 分钟未响应 → 主任；30 分钟 → 合规 |
| 打通 | 一键转「质检结果」或「客诉事件」，避免两套数据 |

原则：**告警是信号不是结论**，不自动判定违规；转为质检结果后才进入复核流程。客户与销售为多对多时，主销售必达、协作销售与主任抄送。

### 12.10 质检报表

报表承担「口径 + 下钻」，看板只做摘要，避免两处重复。

**核心结果指标（4 个，看板与报表共用同一计算源）**

| 指标 | 口径 | 达标线 |
| --- | --- | --- |
| 红线确认数 | 承诺类 + 材料类人工确认数，附占确认风险比 | 越低越好，>0 需核查 |
| 红线涉及客户 | 按客户标识去重，标注高净值 / 私行占比 | 含高净值即预警 |
| 超期未闭环 | 确认后超过 5 天未归档；附高风险未闭环数 | 0 |
| 高风险闭环率 | 高风险已归档 ÷ 高风险确认 | ≥ 90% |

每卡必须带：环比（同长度前一窗口）、状态徽标（达标 / 低于目标 / 需升级）、口径说明。

**报表分区**

| 区块 | 内容 | 关键约束 |
| --- | --- | --- |
| 本期结论 | 自动生成一句：闭环率是否达标、红线集中在哪条规则、超期建议动作 | 文案由指标推导，不手写 |
| 风险趋势 | AI 提示（工作量）与人工确认（结果）双线 | 明确「确认数才是结果」 |
| 处置漏斗 | AI 提示 → 人工确认 → 整改完成 → 已归档，含逐级转化率 | 转化率 = 本级 ÷ 上级 |
| 风险等级分布 | L0 / L1 / L2 占确认数比例 | 合计等于确认数 |
| 风险类型 | 各类型「确认 / 误报」双色条 | 误报率 = 驳回 ÷ 命中 |
| 团队风险密度 | 每千条会话命中数 | 按会话量归一化，避免人多即问题多 |
| 规则质量 | 命中、确认、误报率、红线、重复、处置结论 | 误报率 ≥ 30% 标红并给补充反例建议 |
| 重复违规 | 同人同规则再犯名单与最近时间 | 累计 3 次进入专项培训 |
| 业务量与成本 | 会话量、已质检、覆盖率、判定量、Token、单条与总成本 | 成本 = 判定量 × 820 Token × 2.4 元/百万 |

**口径约束**
- AI 提示 ≠ 违规：提示数随规则收紧上升，确认数才是结果，两者之差为误报，不等同准确率；
- 涉及客户按客户标识去重，涉及员工按姓名去重；
- 时间范围仅支持近 7 / 30 天；环比取前一个等长窗口；
- 规则与团队明细为演示抽样，与汇总口径独立，页面需明示。

其他报表（素材质检、直播间、成本）沿用原指标，作为后续迭代。

### 12.14 质检看板：客户 / 销售双维度

看板按**维度切换**，一次只看一种对象的阶段与原因；公共区（待复核队列、直播告警、计划运行）两个维度共用。时间范围（近 7/30 天）与维度互不影响。

结果指标（红线确认数、红线涉及客户、超期未闭环、高风险闭环率）**只在质检报表出现**，看板不重复展示。

#### 客户维度

| 阶段 | 判定 | 说明 |
| --- | --- | --- |
| 被关注 | 命中 L1/L2 或情绪信号，客户未提诉求 | 7 天未升级可退出 |
| 投诉意向 | 出现投诉、监管、曝光类表述 | 主任介入 |
| 投诉处理中 | 已生成处置任务、处理中 | 超 3 天未结计入超时 |
| 已化解 | 30 天无新增且客户确认 | 复发回到更高阶段 |

区块：KPI 5 → 客户风控趋势（四线，可隐藏）→ 阶段结构 + 本期流转 → 客户风控原因（可筛名单）→ 在险客户名单。

#### 销售维度（原样迁移参考版质检报表）

销售维度不重新设计，直接嵌入《风控合规》原型「质检报表」页的完整内容，代码与样式原样迁移，保证评审时两处对得上：

| 区块 | 内容 |
| --- | --- |
| 页头 | 数据截止日、区间会话数与 AI 提示数 |
| 筛选条 | 开始/结束日期 + 快捷区间（前一天 / 近 7 / 30 / 90 天）+ 导出快照 |
| 总体汇总 | 需立即关注结论条 + 4 个红线指标卡（红线确认数、红线涉及客户、超期未闭环、高风险闭环率） |
| 本期关键问题 | 3 张卡片（规则问题 / 团队问题 / 重复违规），含团队 chips、建议动作、负责人与截止 |
| 汇总概览 | 风险趋势（人工确认主线 + AI 提示工作量）、Top 5 风险对象（人员/团队切换）、风险等级分布、处置漏斗、风险类型分布、团队风险密度、重复违规、业务量与覆盖 |
| 问题与团队详情 | 问题清单（可打开规则详情弹窗）、团队问题对比、行动跟踪 |
| 口径脚注 | AI 提示 ≠ 违规，两者之差为误报，不等同准确率 |

集成约束：

- 迁入部分的选择器统一加 `.rpt-scope` 作用域，避免与外壳同名类（`.panel`、`.verdict`、`.tag`、`.notice`）互相污染；
- 区间选择属于报表自身状态，与看板客户维度的 7/30 天互不影响，切换维度后保留上次所选区间；
- 销售维度不显示看板自带的 7/30 天控件与导出按钮，避免两套控件并存。

#### 通用约束

- 客户阶段为**互斥存量**：同一客户同一时刻只处于一个阶段，四阶段合计等于质检客户数；
- 客户维度的 7/30 天与「质检报表」页共用同一状态；销售维度使用报表自身的区间选择；
- 阶段 ≠ 严重度：严重度仍按 L0/L1/L2，阶段只描述对象位置与停留时长；
- 退出观察（客户流失 / 销售离职调岗）单独计数，不并入四阶段；复发单独统计；
- 图中末点、KPI、结构条、名单计数必须同源推导；
- 点客户/销售名称跳「质检结果」并按姓名预筛。
