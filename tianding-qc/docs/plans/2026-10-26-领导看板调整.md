# 企业数据资产中心领导看板调整计划

目标：将已讨论的领导视角方案落实为可独立打开、可追溯明细的 HTML 副本。

技术：沿用原生 HTML/CSS/JavaScript、IndexedDB，无新增运行依赖。

## 范围与文件

- 输出 `企业数据资产中心-领导看板版.html`，默认进入看板；上传存储使用独立数据库名。
- 构建材料和验证产物保存在 `outputs/leader-board/`。
- 新增 `tests/leader-board.spec.py`，检查统计、下钻、导出、原页面回跳与响应式。
- 保留源文件，以 SHA-256 对照验证。无 Git 操作。

## 实现步骤

1. 从实际留存的客户、会话、版本审核、咨诉、退款及处理历史生成统一统计模型。
2. 重排重点关注、当前概况、期间流转与团队分布、内容使用、数据可信度五个区块。
3. 为所有指标及明细入口提供同口径列表，支持原记录、客户档案、实际发送版本及原消息回跳。
4. 看板导出包含统计范围、截止时点、指标与明细；列表导出保持当前下钻范围。
5. 执行独立 Chromium 回归，检查桌面、窄屏、键盘、空数据和异常分支，截图验收。
6. 完成后安排多 Agent 对抗性审查业务口径和交互回归，再修复必要问题。

## 口径与风险

- 快照固定为 2026-10-23 16:35；期间为截至快照的近 7/30 个自然日，当前存量不受期间切换影响。
- 原聚合数字不再用于新看板，全部数字回溯现有样本。目录样本和有实际业务记录的客户分开展示。
- 没有足够历史，不给出环比或风险存量收缩结论；趋势只展示有明确发生时间的咨诉登记/办结事件。
- 咨诉和退款分开列明；没有明确截止时间不判超期；申请金额不等于最终应付金额。
- 客户表达只作为演示规则线索，来源经办/实际联络不等于责任认定。
- 审核合规按实际发送版本和发送前审核记录核对；缺失记录单列待核实。
- 关键记录齐备率检查明确关联的记录类型，不宣称原件法律效力或全量覆盖。
- 新增本地上传发生在固定快照之后，不纳入该期看板；仍可在资产检索中查阅。
