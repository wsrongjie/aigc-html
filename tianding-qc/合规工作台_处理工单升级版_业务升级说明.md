# 合规工作台 · 处理工单升级版 业务升级说明

> 对比对象
> - 老版：`合规工作台_规则模型无版本_可交互原型.html`
> - 新版：`合规工作台_处理工单升级版_可交互原型.html`
>
> 本文只讲业务上补了什么、为什么补，不做功能点罗列。

---

## 一、一句话结论

老版回答的是「**能不能检出、谁来复核**」；
新版补齐的是「**等级凭什么这么定、证据从哪来、责任落到谁、闭环怎么收**」。

创作/运营链路从原来的两段（预警 → 复核）延长成完整一条：

```
数据接入 → 检测批次 → 预警复核（认定） → 等级策略（定级） → 处理工单（销售处置） → 风控验收 → 事件闭环
```

同时把全站角色词从「质检」统一为「风控」（质检验收 → 风控验收、质检批次 → 风控检测批次、质检确认 → 风控确认），这不是改文案，是把**责任主体**从"质检团队"上移到"风控团队"。

---

## 二、六块业务补充

### 1. 定级逻辑：从「模型说了算」到「模型出标签、策略算等级」

老版只有模型+规则，等级是模型直接给的，改一次规则就要重跑一遍模型。新版把「定级」抽成独立模块（新增左侧导航 **等级策略**）。

业务上落了三件事：

- **一个场景一套策略**：质检规则场景给"结果等级"，策略决定"要不要往上抬、抬几档"。计划必须绑定策略才能发布，未绑定的场景在列表里直接标红提示。
- **上升规则可配**：N 天观察窗口、按次数阶梯升档、重点节点一次顶格、多标签叠加、情绪加成、封顶等级，以及"计数范围"（全部有效排除误报 / 仅已确认）。
- **等级可解释**：事件详情里能看到完整推导链——`AI 原始 T3 → 基准 T2 → 最终 T1`，后面跟着"本场景第 3 次触发 → 阶梯升 1 档""多标签叠加 +1 级""升档封顶 T0"这样的中文原因。

另外配套两个"敢改"的保障：策略有版本和启停，**改策略不重跑模型**；配置弹窗里能先看影响面（覆盖多少条本场景事件、多少条等级会变化）再保存。

> 业务价值：客户最容易挑战的一句是"凭什么这条判 T0"。以前只能说"模型判的"，现在能给出一条可复述、可对账的规则链；同时把"调参"从"重跑模型"降级成"改配置"。

---

### 2. 复核环节：从「一条会话截图」到「多渠道证据 + 只做认定」

- **证据按来源差异化呈现**：企微会话（原始消息顺序 + 命中片段高亮）、文字直播间评论（房间/场次/主播/同一场次评论顺序，区分主播、客户、其他观众）、客诉留言（留言正文 + 附件 + 联系方式脱敏）、客诉录音（波形 + 说话人分离 + 带时间轴的转写片段）。以前所有来源都被渲染成"企微聊天记录"。
- **渠道进入筛选维度**：渠道页签带数量，和事件类型、风险等级筛选联动，空渠道自动置灰。
- **复核结论收敛为两种**：确认风险 / 判定误报，"待补证"被并入待确认并从结论里移除（补证成本高、责任不清）。复核页只保留认定动作，建单、观察、处置推进都从这里分流出去。
- **重复触发显性化**：队列上直接标"屡犯 · 第 3 次"并高亮，详情里给出"该客户近 30 天内第 N 次风险"和历史记录入口——这是投诉升级最关键的判断依据。

> 业务价值：客诉风险天然跨渠道（企微抱怨 → 直播间追问 → 客服留言 → 打电话），只做一个渠道的质检永远看不到全貌；而复核岗被明确限定为"认定者"而不是"流程推进者"，职责边界清楚了。

---

### 3. 处置环节：工单从「一个弹窗」升级为可运营的流水线（本次升级主体）

老版工单只有一张列表 + 一个弹窗，四个状态里有两个是同一件事。新版把它当成一条真正的处置流水线来做：

**(1) 阶段定义写死**
`风控确认 → 销售处理（在 CRM）→ 风控验收 → 解决关闭`。
验收通过即关闭，并同步解除风险事件，**不再有二次人工确认**；退回则必须写退回原因、需补材料、给新的截止时间，工单退回"销售处理中"，历史提交记录全部保留。

**(2) 工单类型 = 处置模板**
每种风险对应一套"默认处理要求 + 验收清单"（例如投诉类要求核实事实、联系客户、提交回访记录）。模板只对新建工单生效，不改历史工单的验收口径。

**(3) 时效按等级分档**
T0/T1/T2/T3 各配处理时限，另有兜底档。时限只给新建工单一个默认值，人工可调；**转派和退回都不重置原期限**——避免"一转派就无限续期"。

**(4) 指派与提醒分离成两件事**
指派规则只管"建单时默认给谁"（客户归属销售优先 / 主管优先），转派另走审批；提醒配置按阶段配（确认超时、销售超时、验收超时、关闭后回访），每个阶段可选提醒对象（责任人/直属主管/复核人/风控负责人）、渠道（站内 + 企微）、触发时机，还带去重、兜底和免打扰，**同一工单、同一阶段、同一触发点只发一次**。

**(5) 岗位视角分开**
销售视角只能填跟进、交材料、提交验收，不能改状态、不能覆盖已提交材料；风控视角才能验收/退回。风控不代销售填写处理结果，这是责任边界。

**(6) 手工催办始终可用**
自动提醒可以关，但手动催办不受开关限制，且支持批量（批量只允许导出与催办，**不允许批量验收或关闭**）。导出的 CSV 和导出记录都留痕。

**(7) 列表是给人天天用的**
列设置可按岗位调整（至少保留 3 列，操作列固定）、视图预置（待验收 / 逾期工单 / 重复风险客户 / 我的待办）、高级筛选（含检测来源、工单类型、主责任人、时效状态）。

> 业务价值：客户真正的痛点不是"识别不出来"，而是"识别出来以后没人管、管了没人验、验完没人跟"。新版把"谁在什么时候必须做什么、超时提醒谁、材料不够怎么退回"全部写成配置项，处置过程可审计、可追责。

---

### 4. 数据底座：从「7 个数据源只读展示」到「每个源可配可验证」

老版系统配置里数据源是一张静态表（名字、用途、状态、最新同步）。新版逐个可配置：

- 接入方式：API 拉取 / API 推送（Webhook）/ 会话存档同步 / 文件导入 / 人工上传
- 同步频率、延迟要求（分钟）、历史回溯（天）、接口地址与 AppID/密钥
- **字段映射**：源字段 → 目标字段（内容文本、录音或媒体地址等），并可标记**身份主键**
- 保存前校验：至少一个身份主键（客户跨渠道合并的前提）、至少一个内容或证据字段、映射不许留空
- 连通性测试、启停、同步状态

同时新增 **分类分级字典**（分类 → 分级项 + 备注），规则里的等级可以直接从分类分级导入，导入后仍需人工补判定标准、排除条件、必要证据。

> 业务价值：客户第一次评审必问的两个问题——"能不能接我们自己的系统""能不能用我们自己的分级口径"——现在在原型里都有明确的承接位置，而不是留白。

---

### 5. 批次与台账：从示例表格到数据驱动

- 「质检批次」更名 **风控检测批次**，列表按批次数据排序，详情里能联查本批次生成的事件抽样与工单进度，失败明细单独重试（重试补原批次，不重复创建事件）。
- 风险事件升级为**总台账**：类型 / 等级 / 状态筛选 + "只看重复触发"，并明确注明"待确认在预警与复核完成认定，结论落库后状态随之更新"。
- 演示数据大幅扩充：4 类渠道证据、同一客户多条历史、多轮提交与多次退回的工单，能完整讲一遍"抱怨 → 升级投诉 → 建单 → 退回 → 补齐 → 验收关闭"。

> 业务价值：评审时可以按真实故事线走完全程，而不是每页都是互不相干的数据。

---

### 6. 口径与边界统一（最容易被忽略，但对客最有说服力）

新版在页面上明确写死了几条边界，避免客户在会上追问"那这个是不是也能做"：

- 工单**只配处置执行环节**，不改风险规则、模型、计划及复核策略；
- 跨渠道身份合并、累计升级策略**不在本轮工单改造范围**（只在数据源里声明身份主键）；
- 本地演示只登记提醒记录与导出行为，不代表真实消息发送或线上审批；
- 复核结论只有"确认 / 误报"，历史"待补证"已并入待确认，并留有迁移说明。

## 三、差异一览

| 维度 | 老版 | 新版 |
|---|---|---|
| 角色主体 | 质检（质检确认 / 质检验收） | 风控（风控确认 / 风控验收 / 风控检测批次） |
| 等级来源 | 模型直接给等级 | 模型出标签 + 等级策略算最终等级，全链路可解释 |
| 定级调参 | 改规则需重跑模型 | 策略可配、可版本、可启停、可先看影响面 |
| 复核证据 | 统一按企微会话渲染 | 企微 / 直播间 / 客诉留言 / 客诉录音 分渠道呈现 |
| 复核结论 | 确认 / 观察 / 误报 / 待补证 四种 | 确认 / 误报 两种，其余动作分流到处置 |
| 工单 | 列表 + 弹窗，状态定义重叠 | 四阶段流水线 + 类型模板 + 时限 + 指派 + 阶段提醒 |
| 工单退回 | 无标准退回动作 | 退回必须写原因、需补材料、重设截止，多轮留痕 |
| 岗位视角 | 单一视角 | 销售视角 / 风控视角分离，权限即责任 |
| 催办与导出 | 无 | 自动提醒 + 手动批量催办 + 列配置 + CSV 导出留痕 |
| 数据源 | 静态展示表 | 逐源配置接入方式、鉴权、字段映射、身份主键、连通性测试 |
| 分类分级 | 无独立字典 | 新增分类分级字典，规则可引用导入 |
| 批次 | 静态示例 | 数据驱动，可联查事件与工单，失败可重试 |

## 四、对客评审怎么讲（三个建议场景）

1. **"为什么这是 T0？"** → 打开等级策略 + 事件里的等级推导链，讲"模型出标签、策略按次数升档、封顶 T0"。
2. **"客户在直播间骂完又去官网留言，你们看得见吗？"** → 复核页切渠道页签，展示同一客户跨渠道证据和重复触发第几次。
3. **"识别出来以后到底谁在管？"** → 用一条工单走完 提交 → 退回补材料 → 再提交 → 验收关闭，讲清风控只提醒和验收、销售在 CRM 处理。

---

## 五、仍存在的缺口（建议下一轮）

1. **发布前检查清单**：目前只提示"未绑定策略的计划不能发布"，缺一个统一的"发布前自检"面板（模型、规则、策略、计划、复核团队一次校验完）。
2. **跨渠道身份合并**：数据源层声明了身份主键，但客户档案还没有真正合并后的视图，重复触发计数也仍是按单库事件算。
3. **CRM 回写仍是模拟**：销售侧处理发生在 CRM，原型里的提交/回写是本地模拟，真实联通方式（接口、幂等、失败补偿）未定义。
4. **"待补证"出口**：从复核结论移除后，如果确实是证据缺失，目前只能判误报或走工单退回，缺少一条"向销售要材料但不建单"的轻量通道。
5. **模型质量口径**：模型质量页仍按"AI 原始等级"统计确认率/误报率，升级后应补一列"策略生效后的最终等级"对比，否则无法回答"策略到底抬对了几条"。
