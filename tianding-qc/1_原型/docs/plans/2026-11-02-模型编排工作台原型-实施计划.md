# 模型编排工作台原型 Implementation Plan

> **For Codex:** 依次完成单文件原型、静态断言、交互验证与视觉检查；不执行 Git add / commit / push。

**Goal:** 交付一个面向内部产品、算法运营与研发的受约束模型编排工作台单文件交互原型。

**Architecture:** 使用原生 HTML/CSS/JavaScript 维护独立工作流状态；工作流列表、受约束画布、节点配置、测试运行、版本发布和 Token 计费共用同一数据模型。通过独立 localStorage Key 与现有合规工作台隔离。

**Tech Stack:** HTML5, CSS Grid/Flexbox, SVG, Vanilla JavaScript, Python 静态回归检查。

---

### Task 1: 建立原型数据和页面骨架

**Files:**
- Create: `模型编排工作台_可交互原型.html`

**Steps:**
1. 定义视觉 token、左侧导航、顶栏和主内容容器。
2. 建立工作流、工作流版本、节点、连线、执行记录的演示数据。
3. 实现列表、模型服务和执行计费三个导航页。

### Task 2: 实现受约束编排画布

**Files:**
- Modify: `模型编排工作台_可交互原型.html`

**Steps:**
1. 建立节点面板、分阶段画布和 SVG 连线。
2. 实现节点选中、新增、复制、启停、排序和受依赖约束的删除。
3. 在右侧配置栏提供业务模式和高级模式。
4. 提供条件分支、并行分支和汇聚节点的明确视觉语义。

### Task 3: 实现测试、发布和计费反馈

**Files:**
- Modify: `模型编排工作台_可交互原型.html`

**Steps:**
1. 实现测试抽屉和节点执行时间线。
2. 模拟逐节点运行、失败、重试、Token 使用和费用统计。
3. 只允许最新配置测试通过后发布，发布时必填版本说明。
4. 展示工作流版本与风控模型 Step 1“基础模型”的绑定关系。

### Task 4: 建立回归检查

**Files:**
- Create: `tests/模型编排工作台.spec.py`

**Steps:**
1. 断言必要页面、节点类型、交互函数和独立 localStorage Key 存在。
2. 提取脚本并使用 `node --check` 验证 JavaScript 语法。
3. 运行 Python 回归检查，记录通过项。
4. 启动本地静态服务进行浏览器视觉和交互检查；如环境不支持，明确标注未验证边界。
